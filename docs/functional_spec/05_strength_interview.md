## 3. UI 구성

- 뒤로가기 (이탈 시 진행 상태 안내)

### 3.2 인터뷰 진행률 표시 `v1.2 수정`

> 코어 질문 수를 **5개로 확정** (Option A 채택). 프로그레스 바는 5개 기준으로 표시.

- follow-up 질문은 카운트에 포함하지 않음 (코어 질문만 카운팅)

### 3.4 입력 영역

### 3.5 인터뷰 완료 버튼 `v1.2 수정 — 완료 버튼 활성화 시점 확정`

| --- | --- | --- |
| 비활성 | AI `session_end: false` 상태 | opacity 0.45, pointer-events: none |

- 활성화 시 힌트 텍스트 ("코어 질문 5개를 모두 답하면 활성화돼요") 자동 숨김

## 4. 인터뷰 문항 구조 `v1.2 수정`

> **설계 원칙 변경**: 기존 Q1~Q6 고정 질문 방식 → AI가 MCC 코칭 원칙에 따라 자유 변형하는 가변 흐름으로 확정.
> Q1~Q6 목록은 아래 "탐색 방향 가이드"로 성격을 바꿔 참고용으로 유지.

### 4.1 문항 구조

| 단계 | 문항 수 | 목적 |
| --- | --- | --- |
| 오프닝 | 1~2문항 | 긴장 완화, 자연스러운 이야기 유도 |
| 탐색 | 3~N문항 | 4개 도메인 패턴 파악 (실행/영향/관계/전략적사고) |
| 수렴 | 판단 시점 | Top 5 후보 안정화 확인 |
| 클로징 | 마지막 1문항 | 사용자가 스스로 정리하도록 유도 |

- **최소 5문항 / 최대 20문항**
- AI가 수렴 조건(§4.3) 충족 시 조기 종료 가능
- 5개 도메인 이후부터 `session_end: true` 반환 가능

### 4.2 탐색 방향 가이드 (AI 참고용, 고정 스크립트 아님)

AI는 아래 방향을 참고하되, 사용자 답변에서 나온 언어로 자유롭게 변형한다.

| 도메인 | 탐색 방향 예시 |
| --- | --- |
| 실행력 (E) | 마감, 완수, 루틴, 책임, 꼼꼼함, 시스템 관련 경험 |
| 영향력 (I) | 설득, 주도, 발표, 관계 확장, 인정받는 순간 |
| 관계구축 (R) | 신뢰, 공감, 팀, 개인적 연결, 타인의 성장 |
| 전략적사고 (T) | 아이디어, 분석, 패턴 인식, 학습, 미래 구상 |

> 기존 Q1~Q6 고정 질문 목록은 위 탐색 방향에 흡수됨. AI가 사용자 발화를 바탕으로 자유롭게 질문을 구성하므로 고정 스크립트를 spec에 명시하지 않음.

### 4.3 조기 종료 판단 기준 (AI)

아래 두 조건이 **동시에** 충족될 때 `session_end: true` 반환:

1. **도메인 커버리지**: 4개 도메인 각각의 강약 패턴이 답변에서 드러난 상태
2. **Top 5 후보 수렴**: 추가 답변이 더해져도 현재 Top 5 후보가 바뀌지 않을 것으로 판단

→ 조기 종료 시 클로징 질문 1개를 거쳐 자연스럽게 마무리.
→ 20문항 도달 시 수렴 여부와 무관하게 강제 종료.

### 4.4 follow-up 정책

AI가 답변을 평가하여 아래 조건에 해당하면 follow-up 질문 생성:

| 트리거 | 예시 답변 | Follow-up 예시 |
| --- | --- | --- |
| 답변이 지나치게 짧거나 추상적 | "잘 모르겠어요" | "구체적인 상황 하나를 떠올려본다면?" |
| 핵심 키워드 부재 | 행동 묘사 없음 | "그때 어떤 행동을 했는지 더 들을 수 있을까요?" |
| 모순 탐지 | 이전 답변과 충돌 | "앞에서 X라고 하셨는데, 어떻게 연결되나요?" |

- follow-up 진행률 카운트 제외 (코어 질문만 카운팅)

## 5. AI 시스템 프롬프트 설계

> 상세 AI 명세는 `docs/ai_spec/01_strength_interview.md` 참조.

- **코칭 모드**: GENERAL (일반 코칭)
- **코칭 기반**: MCC(Master Certified Coach) 원칙 — 코치가 먼저 결론 제시 금지, 사용자 발화에서 출발
- **강점 프레임**: 갤럽 CliftonStrengths 34 테마 참조, "확정 진단"이 아닌 "관찰된 강점 후보"로 활용
- **강점명 비공개**: 대화 중 강점 명칭을 먼저 언급하지 않음. 사용자는 p06 결과 화면에서 처음 확인
- **개인화**: `profiles.nickname`, `job_field`, `career_level`을 시스템 프롬프트에 치환 주입
- **출력 형식**: 매 응답마다 JSON 반환 (`session_end`, `message`, `top5`, `summary`, `confidence`)
- **시간 정책**: 즉시 적용 — 도출된 결과는 W1부터 시작

| 기능 | 동작 |

| 인터뷰 완료 | `session_end: true` 수신 → 완료 버튼 활성화 → 클릭 시 `strength_analyses` INSERT → 06 이동 |

## 7. 자동 저장 정책

> ⚠️ **schema 정책**: 대화 원문은 DB에 저장하지 않음 (v0.2 결정). 아래 정책은 브라우저 메모리 기반.

- 사용자 입력 전송 시 `sessionStorage.draft_strength_interview`에 대화 전체 백업
- 전송 실패 시 재시도 큐 (최대 3회, 지수 백오프 1s/3s/9s)
- 3회 실패 시 사용자에게 안내 + 재시도 버튼
- 다른 디바이스 진입 시 복원 불가 (DB 미저장). 처음부터 재진행 안내.

## 8. 인터뷰 재개 (Resume)

사용자가 인터뷰 도중 이탈 후 같은 브라우저에서 다시 진입한 경우:

- `sessionStorage.draft_strength_interview` 존재 여부 확인
- 데이터 존재 시: 이어서 하기 / 처음부터 선택 다이얼로그 노출
  - "이어서 하기" → sessionStorage에서 대화 복원, 마지막 AI 질문 표시
  - "처음부터" → sessionStorage 초기화, 새 인터뷰 시작
- 데이터 없음 (브라우저 닫힌 후 재진입) → 처음부터 시작

> ⚠️ **schema 불일치 수정 완료**: `coaching_sessions` 테이블은 v0.2에서 삭제됨. sessionStorage 기반으로 대체.

## 9. 예외 처리

| 상황 | 처리 |
| --- | --- |
| 빈 메시지 전송 시도 | 차단 |
| AI API 응답 지연 (>5초) | 로딩 인디케이터 + 타임아웃 안내 |
| AI API 오류 (5xx) | 재시도 버튼, 3회 연속 실패 시 고객 문의 안내 |
| AI 응답 JSON 파싱 불가 | 오류 로그 기록, "잠시 후 다시 시도" 안내 |
| 네트워크 단절 중 입력 | 큐 적재, 연결 시 자동 전송 |
| 위기 신호 감지 (자살/자해) | 즉시 인터뷰 일시 중단 + 자살예방상담전화 1393 안내 |
| PII 입력 감지 | 입력란 위 경고 + 마스킹 안내 |
| 부적절한 AI 응답 | 안전 메시지로 대체 |
| 세션 만료 (JWT) | 토큰 갱신 후 재시도 |
