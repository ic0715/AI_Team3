# 04. 강점 선택

> 갤럽 클리프턴 스트렝스 34개 테마 중 자신을 가장 잘 나타내는 강점 5개를 사용자가 직접 선택하는 화면. AI 인터뷰나 결과지 업로드 없이, 4개 도메인으로 색깔 구분된 칩에서 곧바로 선택한다.

---

## 1. 화면 개요

| 항목 | 내용 |
| --- | --- |
| 화면 ID | 04_strength_choice |
| 페이즈 | DISCOVER |
| 역할 | 사용자가 갤럽 34개 테마에서 Top 5 강점 직접 선택 |
| 이전 화면 | 03 기본 정보 |
| 다음 화면 | 07 커리어 인터뷰 인트로 (강점 결과 화면 우회) |

---

## 2. 진입 조건

- 사용자 상태 = ONBOARDING
- 03 기본 정보 입력 완료 후 (`profiles.profile_completed = true`)
- `strength_analyses` 테이블에 `is_latest = true` 인 결과가 없는 경우
- 또는 15에서 강점 재분석 요청 시

> ※ 본 화면은 **직접 선택 경로** 전용. AI 인터뷰(05) 경로는 production 풀 스펙에서 별도 진입점으로 유지하되, 기본 흐름은 04 직접 선택을 우선한다. 갤럽 결과지 PDF 업로드 경로는 v2.0에서 폐지.

## 3. UI 구성

### 3.1 상단 바

- 뒤로가기 ← → 03
- 페이지 타이틀: "강점 선택"
- 프로그레스: 2 / 5 단계 (40%)

### 3.2 인트로

- Eyebrow: "STEP 2"
- 타이틀: "나의 강점 **5가지**를 골라주세요 💡"
- 서브: "강점은 갤럽 클리프턴 스트렝스 34개 테마를 기반으로 해요."

### 3.3 도메인 섹션 (4개)

34개 테마는 **4개 도메인**으로 분류되며, 도메인별로 별도 색상을 부여한다. 각 도메인 섹션은 도메인 헤더 + 도메인 설명 + 칩 그리드로 구성.

| 도메인 (한글) | 영문 | 색상 (액센트) | 배경 (연한) | 테마 수 | 도메인 설명 |
| --- | --- | --- | --- | --- | --- |
| 실행력 | Executing | `#7C3AED` 보라 | `#F3EEFF` | 9 | 결과를 만들어내고 일을 해내는 데 능한 강점들. "어떻게(How) 일을 끝낼 것인가"에 집중. |
| 영향력 | Influencing | `#EA580C` 주황 | `#FFF1E6` | 8 | 다른 사람을 설득하고 이끌며 변화를 만들어내는 강점들. 팀의 목소리를 키우고 메시지를 전달. |
| 대인관계 구축 | Relationship Building | `#2563EB` 파랑 | `#E6EFFF` | 9 | 사람들과 깊고 의미있는 관계를 만들고 팀의 결속력을 높이는 강점들. |
| 전략적 사고 | Strategic Thinking | `#059669` 초록 | `#E3F8EE` | 8 | 정보를 분석하여 더 나은 결정을 내리고, 미래의 가능성을 그려내는 강점들. |

> 도메인 분류와 색상 매핑은 **클라이언트 상수**로 관리. 갤럽 공식 4-Domain 체계를 따름.

### 3.4 강점 칩 (총 34개)

각 도메인 섹션 안에 칩 형태로 나열. 칩 데이터는 갤럽 공식 한국어 번역 기준.

#### 실행력 (Executing) — 9개
성취 / 정리 / 신념 / 공정성 / 심사숙고 / 체계 / 집중 / 책임 / 복구

#### 영향력 (Influencing) — 8개
행동 / 주도력 / 커뮤니케이션 / 승부 / 최상화 / 자기확신 / 존재감 / 사교성

#### 대인관계 구축 (Relationship Building) — 9개
적응 / 연결성 / 개발 / 공감 / 화합 / 포용 / 개별화 / 긍정 / 절친

#### 전략적 사고 (Strategic Thinking) — 8개
분석 / 회고 / 미래지향 / 발상 / 수집 / 지적사고 / 배움 / 전략

> ⚠️ **갤럽 공식 한국어 명칭 정렬 필수**: PDF (CliftonStrengths 테마 한국어 가이드, 2022) 기준. 본 spec은 다음 5개 명칭이 갤럽 공식 번역과 일치함을 확인했음 — **심사숙고**(Deliberative, 구 "신중함"), **승부**(Competition, 구 "경쟁"), **개발**(Developer, 구 "발전"), **긍정**(Positivity, 구 "긍정성"), **회고**(Context, 구 "맥락").
>
> ⚠️ 강점명 "회고"(Context)는 앱 내 다른 기능명 "회고하기"(reflection, weekly retro)와 단어 충돌이 있음. 향후 "회고(Context)" 식 영문 병기로 구분 강화 검토.

### 3.5 칩 인터랙션

| 상태 | UI |
| --- | --- |
| 기본 | 도메인 배경(연한 톤) + 도메인 색 외곽선 + 강점명 |
| Hover | 외곽선 강조, 살짝 lift |
| 선택됨 (Selected) | 도메인 색상 fill + 흰색 텍스트 + 체크 아이콘 |
| 비활성 (Disabled) | 5개 이미 선택된 상태에서 미선택 칩들. 탭 무시 |

- 단일 칩 탭 토글 — 다시 탭하면 선택 해제
- 5개 선택 도달 시 미선택 칩들 자동 disabled 처리 → 선택 해제 시 다시 활성화

### 3.6 하단 선택 요약 + Bottom CTA

하단 푸터는 3단 구조로 구성된다 (position: sticky; bottom: 0).

**① 선택 강점 칩 목록** (최상단)
- 선택한 강점을 도메인 색상 pill 형태로 가로 나열
- 각 칩: `강점명 ✕` — 탭 시 해당 강점 선택 해제 (위로 스크롤 없이 바로 취소)
- 선택 0개일 때: "강점을 선택하면 여기에 표시돼요" 안내 문구 표시

**② 카운터 뱃지 + CTA 버튼** (한 줄 가로 배치)
- 카운터 뱃지: `N / 5` — 5개 완성 시 accent 색상으로 강조
- **CTA**: "다음으로 →" — 정확히 5개 선택 시에만 활성화 → 클릭 시 `strength_analyses` INSERT → 07 이동

## 5. 데이터 정책

- **저장 위치**: `strength_analyses` 테이블
- **저장 시점**: "다음으로" 버튼 클릭 시 일괄 저장
- **저장 컬럼**:
  - `method` = `'direct_select'` (신규 enum 값. 기존 `'ai_interview'`와 병렬. v2.0: `'gallup_upload'` enum은 폐지)
  - `strengths` JSONB — `[{rank: 1~5, name_ko, name_en, domain}]` 배열. rank는 사용자 선택 순서가 아닌 단순 표시 순번 (Option B 정책: 순위 의미 없음)
  - `is_latest` = `true` (DB 트리거가 기존 row의 is_latest를 자동 false 처리)
- **클라이언트 임시 저장**: `localStorage.selectedStrengths` (JSON 배열, 다음 페이지에서 prefill용)
- **AI 시스템 프롬프트 컨텍스트로 활용**: 07 → 08 커리어 인터뷰, 13 회고 코칭에서 시스템 프롬프트에 주입

> ⚠️ **schema 반영 필요 항목**: `strength_analyses.method` enum 값에 `'direct_select'` 추가 필요. v2.0에서 `'gallup_upload'` enum 폐지로 `'ai_interview'`와 `'direct_select'` 2종 운영. `file_url` 컬럼도 함께 폐지(또는 향후 도입 시 부활 검토).

## 8. 접근성

- 도메인 섹션은 `role="group"` + `aria-labelledby` (도메인 헤더 id 참조)
- 칩 그룹은 `role="group"` (단일 선택 radio가 아닌 다중 선택 toggle group이므로 button + aria-pressed 패턴 권장)
- 각 칩은 `aria-pressed="true|false"`로 선택 상태 알림
- 카운터 뱃지는 `aria-live="polite"` + `aria-atomic="true"`
- 푸터 선택 칩 목록 컨테이너: `aria-live="polite"` + `aria-label="선택한 강점 목록"`
- 푸터 칩 ✕ 버튼: `aria-label="{강점명} 선택 해제"` 로 스크린 리더 구분
- 색상만으로 도메인을 구분하지 않음 — 도메인 헤더 텍스트 + 한·영 표기로 식별 보강
- 키보드: Tab으로 칩 간 이동, Space/Enter로 토글
- WCAG AA: 도메인 색상의 명도 대비 4.5:1 이상 검증 필요

- 34개 칩 일괄 렌더 (가상화 불필요, 단순 div 그리드)
