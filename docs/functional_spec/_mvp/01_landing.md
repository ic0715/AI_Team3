# 01. 랜딩 / 코칭 합의

> 서비스를 처음 방문한 사용자에게 코칭 원칙(고객 주도·강점 기반·코칭 범위)을 안내하고, 동의 후 회원가입/로그인으로 자연스럽게 유도하는 화면.

## 1. 화면 개요

| 항목 | 내용 |
| --- | --- |
| 화면 ID | 01_landing |
| 페이즈 | ONBOARDING |
| 역할 | 서비스 진입, 코칭 방식 안내, 가입/로그인 유도 |
| 진입 경로 | 직접 URL 접속, 마케팅 링크, 검색 결과 |
| 다음 화면 | 02 로그인/회원가입 |

## 2. 진입 조건과 라우팅

사용자 상태별로 본 화면 노출 여부가 결정됨. 이미 로그인된 사용자는 본인의 상태에 맞는 화면으로 자동 리다이렉트.

| 사용자 상태 | 동작 |
| --- | --- |
| GUEST (비로그인) | 본 화면 정상 노출 |
| UNVERIFIED (이메일 미인증) | NEW01 이메일 인증으로 자동 리다이렉트 |
| ONBOARDING (온보딩 진행 중) | 마지막 진행 단계 화면으로 자동 리다이렉트 (아래 2.1 참조) |
| PAUSED (목표 일시중단 중) | 11 홈으로 자동 리다이렉트 (중단됨 배지 표시) |
| ACTIVE (12주 진행 중) | 11 홈으로 자동 리다이렉트 |
| COMPLETED (12주 완료) | NEW03 12주 완료 화면으로 자동 리다이렉트 |

> **상태 판별 우선순위:** ACTIVE → PAUSED → COMPLETED → ONBOARDING → UNVERIFIED 순으로 체크.  
> active 목표가 있으면 ACTIVE로 처리하여 11 홈으로 이동.

### 2.1 ONBOARDING 리다이렉트 세부 로직

ONBOARDING 상태인 경우, 아래 순서로 DB를 체크해 마지막으로 완료된 단계 다음 화면으로 이동.

```
1. profiles.profile_completed = false  →  03 기본 정보 입력
2. strength_analyses (is_latest=true) 없음  →  04 강점 선택
3. career_interview_results 없음  →  07 커리어 인터뷰 안내
4. career_interview_results.recommended_competencies is null  →  09 커리어 인터뷰 결과
5. goals (active) 없음  →  10 목표 선택 (액션아이템 화면)
```

> `profiles.profile_completed` 컬럼: `profiles` 테이블에 `boolean DEFAULT false` 로 추가.  
> 03 기본 정보 입력 완료 시 `true`로 UPDATE.  
> → **schema v0.7.2에 반영 완료** (spec-schema.md 업데이트됨)

### 2.2 COMPLETED 판별 기준

`goals.status = 'completed'` AND `goals.current_week >= goals.total_weeks`(기본값 12) 인 목표가 있고,  
현재 `active` 목표가 없는 경우 COMPLETED로 판별.

> active 목표가 새로 생성되면 ACTIVE 우선으로 처리됨.

## 3. UI 구성 `v1.7 — swipe deck 5장 구조로 전면 재구성`

세로 스크롤 단일 페이지 → **가로 swipe deck 5장**으로 변경. 한 카드당 한 메시지에 집중, 사용자가 자연스럽게 좌→우 진행하며 신뢰 누적 후 마지막 카드에서 CTA. 컨테이너 가로 폭은 기존 그대로 (`min(430px, 100vw)`).

### 3.1 브랜드 헤더 (고정)

- 좌측: 로고 아이콘 (SVG 웨이브, accent 배경 정사각 둥근 모서리) + 워드마크 "CareerPT"
- 로고 하단 서브타이틀: "내 강점으로 커리어 방향을 찾는 AI 코치" *(v1.6 유지)*
- 우측 로그인 링크: **없음** — 02 탭 전환으로 일원화
- swipe deck 위에 고정 (deck flex 1 / 헤더 flex none)

### 3.2 Swipe Deck (5장)

`scroll-snap-type: x mandatory` 가로 스크롤 컨테이너. 카드 폭 = 컨테이너 폭. 좌우 스와이프 또는 하단 prev/next 버튼으로 이동.

| # | 카드명 | 시각 | 카피 |
| --- | --- | --- | --- |
| 1 | **HERO 캐치프레이즈** | 텍스트 중심 (세로 가운데 정렬) | h2: "검색해도 안 나오는 답은, **당신 안에** 있어요." / 서브: "막막한 커리어, 정답 대신 **좋은 질문**으로 함께 찾아요." |
| 2 | **강점에서 시작** | 이모지 👀 + 텍스트 | h2: "거창할 필요 없어요. **강점 5가지**부터 시작해요." / 서브: "어려운 검사 용어는 없어요. 잘하는 것에서 출발하면 돼요." |
| 3 | **TRUST (신뢰)** | Eyebrow + 체크 리스트 3개 | Eyebrow: "그런데, 믿을 만해요" / h2: "아무 말이나 하는 AI는 **아니에요** 🙅" / 체크리스트(각 한 줄 표시, 12.5px): ① **갤럽 인증 강점코치**와 **글로벌 코치**가 함께 만들었어요 / ② AI 코치는 **MCC급 코치**의 코칭 방식을 학습했어요 / ③ 설계 전 과정에서 **전문 코치진의 자문**을 받았어요 |
| 4 | **JOURNEY (여정)** | Eyebrow + 4-step flow | Eyebrow: "이렇게 진행돼요" / h2: "강점에서 시작해, **12주 뒤**엔 달라져 있어요." / 4단계: ① 강점 고르기 ("내가 가진 것에서 출발") / ② 코치와 대화 ("스스로 답을 꺼내는 과정") / ③ 방향 & 액션 아이템 제안 ("나에 대한 이해 기반") / ④ **12주 실천 & 회고** ("매주 행동하고 돌아보며 진짜 변화로", 강조 카드 — accent 보더) |
| 5 | **OUTCOME + CTA** | 이모지 🚀 + outcome 3장 + Primary CTA | h2: "이제 **시작**해볼까요?" / outcome (체크 + 굵은 텍스트): ① 내 고민에 맞춘 목표 5가지 / ② 바로 할 수 있는 첫 액션 1개 / ③ 12주 실천 & 회고 루틴 / CTA: "로그인하고 시작하기 →" (accent fill, 전체 폭) → `/login?tab=signup` |

> v1.7 결정 배경: 기존 단일 스크롤 페이지에서 코칭 원칙 3장이 텍스트 위주로 길어 이탈률 높음. swipe deck으로 한 카드당 한 메시지로 압축 + TRUST 카드(코치 자격) 신설로 "이거 믿어도 되나?" 우려 해소.

### 3.3 Bottom 네비게이션

- 좌: prev 화살표 (◁) — 첫 카드에서 disabled
- 중앙: dot indicator 5개 — 현재 카드는 길쭉한 pill 형태(accent)
- 우: next 화살표 (▷) — 마지막 카드에서 disabled
- 키보드 ← → 키도 동일 동작 (a11y)

### 3.4 Primary CTA

- 위치: **5번 카드 내부** (별도 sticky footer 없음)
- 카피: "로그인하고 시작하기 →" *(v1.7: "동의하고 시작하기 →" → 마지막 카드 컨텍스트에 맞춰 변경)*
- 동작: `/login?tab=signup` 이동, utm 파라미터 보존
- 별도 Secondary CTA 없음

> 약관 동의 효력은 본 화면에서 발생하지 않음. 실제 동의는 02에서 받음.

## 4. 기능 및 인터랙션

| 기능 | 동작 | 비고 |
| --- | --- | --- |
| Primary CTA 클릭 (카드 5) | 02 로그인/회원가입(`/login?tab=signup`)으로 이동 | utm 파라미터 보존 |
| 스와이프 (좌↔우) | 카드 1↔5 사이 이동, scroll-snap으로 자동 정렬 | 터치/마우스 드래그 |
| prev/next 화살표 클릭 | 한 카드씩 이동. 양 끝에서 disabled | — |
| Dot 클릭 | 해당 카드로 직접 이동 (선택 사항) | 구현 필수 아님 |
| 키보드 ← → | 한 카드씩 이동 | a11y |
| 카드 hover/tap | 미세한 그림자/색 변화 | 정보성 카드, 클릭 동작 없음 |

## 6. 데이터 정책

- **저장 데이터**: 없음
- **동의 효력**: 본 화면에서 발생하지 않음 (02에서 발생)
- **클라이언트 저장소 사용**: 없음

## 7. 분석 이벤트

| 이벤트 | 트리거 | 속성 |
| --- | --- | --- |
| landing_view | 페이지 로드 | utm_source, utm_medium, utm_campaign |
| landing_card_view | 각 카드 진입 시 (1회만) | card_index (1~5), card_name |
| landing_cta_clicked | Primary CTA("로그인하고 시작하기") 클릭 | - |
| landing_deck_completed | 5번 카드 도달 | reached_via (swipe/arrow/dot) |

## 8. 접근성 (WCAG 2.1 AA)

- 모든 카드/버튼에 키보드 포커스 가능, 포커스 인디케이터 명확
- Hero 일러스트에 alt 또는 aria-hidden="true" (장식용일 경우)
- 색약 사용자 대응: 카드 색상 외 아이콘으로 구분
- 글자 크기 200% 확대 시 레이아웃 깨지지 않음
- 명도 대비: 본문 4.5:1 이상, 대제목 3:1 이상

## 9. 성능 목표

- LCP 2.0초 이하 (Hero 이미지 우선 로딩)
- 초기 JS 번들 50KB(gzip) 이하
- 이미지: WebP/AVIF 포맷 + lazy load
- CLS 0.1 이하
