# AI 코치 발화 평가 및 지속 개선 시스템 v2

> CareerPT의 AI 코치가 ICF 코칭 원칙을 지키는지, **그리고 산출물(JSON)이 명세서를 충족하는지, 사용자(페르소나)가 실제로 가치를 느끼는지**까지 3-Layer로 측정하는 룰북.
>
> v0.1과의 차이는 §0 / §5 / §6 / §7 / §8 / §14 (전부 신규). 원본 4 KPI(§2~§4)는 정의·임계값 무변경.
>
> 작성일 2026-05-14 · 범위: 1차 세션(인터뷰+역량선택+액션아이템)만. 회고·12주·강점 인터뷰 평가 제외.

---

## 0. 평가 구조 개요 (3-Layer)

ralph-loop의 종료조건을 정의하기 위해, 평가를 **세 층**으로 나눈다. 각 층의 단위·도구·적용 시점이 다르다.

| Layer | 대상 | 단위 | 방법 | 적용 시점 |
|---|---|---|---|---|
| **A — 발화 품질** | AI 코치의 1턴 발화 | 턴 단위 비율 | LLM-as-judge (cross-vendor) × 4 KPI | #2 인터뷰의 매 턴 |
| **B — 출력 품질** | #3 / #4 의 JSON 산출물 | 세션 단위 룰 위반율 | 결정적 코드 검증 + 재시도/fallback 카운트 | #3 5장 카드 생성 직후, #4 액션 INSERT 직전 |
| **C — 자기평가** | 페르소나가 체감한 가치 | 세션 단위 1~10 자가점수 | 페르소나-LLM 자가 채점 (cross-vendor) | 세션 1회 종료 후 |

```
세션 1회
  ├─ #2 인터뷰 (n턴)        ──► Layer A: 4 KPI 비율 산출
  ├─ #3 역량 5장 카드         ──► Layer B-1: 결정적 검증 + 재시도 카운트
  ├─ #4 액션아이템 3~5건      ──► Layer B-2: 시드풀 위반율 + 재시도 카운트
  └─ 종료                    ──► Layer C: 페르소나 자가채점 4축

session_score = 10 × (0.5·A_norm + 0.3·B_norm + 0.2·C_norm)
```

**종료 조건 (ralph-loop stop criteria)**:
- 34 페르소나 평균 `session_score ≥ 9.0`
- AND 비정형 페르소나 7명 모두 `session_score ≥ 8.0`

> 가중치 0.5/0.3/0.2 와 임계값 9.0/8.0 은 **가설**. baseline 측정 후 §7.3 재조정 예정.

## 1. 배경과 목적

CareerPT의 핵심 제품 약속은 **"AI 코치는 먼저 결론을 정하지 않는다 — 사용자가 말한 표현과 선택을 바탕으로 질문하고 반영한다"** 입니다 (랜딩 페이지 명시).

그러나 LLM은 본질적으로 *답을 생성*하려는 경향이 강하며, 프롬프트 엔지니어링만으로 이 경향을 완전히 억제하기 어렵습니다. 따라서 다음 세 가지가 필요합니다.

1. AI 코치 발화가 코칭 원칙에 부합하는지 **측정 가능한 지표**로 정의 (→ Layer A)
2. AI 산출물(JSON)이 명세서를 충족하는지 **결정적 검증**으로 측정 (→ Layer B, v2 신규)
3. 사용자가 실제로 가치를 느끼는지 **페르소나 자가평가**로 측정 (→ Layer C, v2 신규)
4. 위 셋의 종합 점수로 **프롬프트·few-shot 개선 루프**의 종료조건 정의 (→ §7, v2 신규)

이 문서는 그 시스템의 v2 설계입니다. v0.1의 §1~§9는 Layer A로 포함되어 그대로 살아있습니다.

## 2. 평가 프레임워크 — Layer A (발화 품질)

> **v2 명명**: 이하 §2~§4 전체가 "Layer A"에 해당. 정의·임계값은 v0.1과 동일.

### 2.1 권장 발화 (Coaching behaviors)

| 카테고리 | 정의 | 예시 |
|---|---|---|
| **Powerful Question** | 사용자가 스스로 답을 찾도록 유도하는 개방형·탐색적 질문 | "그 순간 가장 마음에 걸렸던 건 뭐예요?" |
| **Reflection** | 사용자 발화를 자기 언어로 다시 비춰주기 | "그러니까 '시간이 부족해서'가 아니라 '우선순위가 흔들려서'에 가깝네요." |
| **Acknowledgment** | 사용자의 감정·노력을 인정 (판단·평가 없이) | "그 상황에서 그렇게 느낀 거, 충분히 그럴 수 있어요." |
| **Hold space** | 사용자가 더 말할 수 있도록 짧게 머무름 | "조금 더 들려주실 수 있어요?" |

### 2.2 안티패턴 (Anti-patterns)

| 카테고리 | 정의 | 왜 문제인가 |
|---|---|---|
| **Advice giving** | 사용자가 요청하지 않은 조언·권고 | 코칭이 컨설팅으로 변질 |
| **Solution suggesting** | 사용자보다 먼저 해결책 제시 | 사용자의 사고를 가로챔 |
| **Interpretation** | "당신은 ~한 사람이군요" 식의 단정적 해석 | 갤럽 강점도 *후보*로만 쓰기로 한 원칙 위반 |
| **Premature closure** | 충분한 탐색 전에 대화를 정리·요약 | reflection depth가 낮은 채로 종료 |
| **Praise inflation** | 과도한 칭찬·맞장구 | 사용자의 자기 검증을 약화 |

### 2.3 분류 단위

- **단위**: AI의 1턴(turn) = 1개 발화 단위
- 한 턴 안에 여러 카테고리가 섞이면 **주(主) 카테고리 1개 + 부(副) 카테고리 최대 2개** 라벨링
- 안티패턴이 부 카테고리에라도 등장하면 해당 턴은 "혼합 패턴"으로 별도 집계

## 3. Scoring 프로토콜 (Layer A LLM-as-judge)

### 3.1 LLM-as-judge

- **채점 모델**: 생성 모델과 **다른** 모델을 사용 (self-judging bias 방지)
  - 예: 생성은 Claude Sonnet → 채점은 GPT-4o, 혹은 그 반대
- **입력**: (직전 사용자 발화 1~3턴 + 평가 대상 AI 발화 1턴)
- **출력**: JSON `{ primary: <category>, secondary: [<category>...], rationale: <string> }`
- **온도**: 0 (재현성)

### 3.2 인간 검증

- 매 사이클마다 **무작위 30턴**을 두 명이 독립 라벨링
- **Cohen's kappa ≥ 0.6** 일 때 LLM-as-judge 결과를 신뢰
- kappa가 낮게 나오면 → 루브릭 정의 자체를 재검토

### 3.3 채점 프롬프트 (v0 초안 유지)

```text
당신은 ICF 코칭 윤리 강령에 정통한 평가자입니다.
다음은 AI 코치와 사용자 간 대화의 일부입니다.
[직전 사용자 발화]: ...
[평가 대상 AI 발화]: ...

이 AI 발화를 다음 카테고리 중 하나로 분류하세요.
- powerful_question / reflection / acknowledgment / hold_space
- advice / solution / interpretation / premature_closure / praise_inflation

규칙:
1. "조언 같은 질문"(예: "X 해보는 건 어떠세요?")은 advice로 분류합니다.
2. 사용자 단어를 그대로 되돌려주는 건 reflection입니다.
3. 분류 근거를 한 문장으로 적으세요.

JSON으로만 답하세요.
```

## 4. Layer A 핵심 KPI (4지표, v0.1 무변경)

| 지표 | 정의 | 목표 | 측정 빈도 |
|---|---|---|---|
| **Coaching Ratio** | (powerful_question + reflection + acknowledgment + hold_space) / 전체 AI 턴 | **≥ 80%** | 세션 1회 |
| **Anti-pattern Rate** | (advice + solution + interpretation + premature_closure + praise_inflation) / 전체 AI 턴 | **≤ 10%** | 세션 1회 |
| **Question Density** | powerful_question / 전체 AI 턴 | **≥ 40%** | 세션 1회 |
| **Mixed Turn Rate** | 부 카테고리에 안티패턴이 섞인 턴 비율 | **≤ 15%** | 세션 1회 |

### 4.1 LayerA_normalized 환산 (v2 신규)

세션 1회당 4 KPI → 0.0~1.0 정규화. 각 KPI는 "목표 충족 = 1.0, 임계 위반 = 0.0"의 **선형 매핑**.

```
score_CR  = clip( (Coaching_Ratio   - 0.50) / (0.80 - 0.50), 0, 1 )   # 50%→0, 80%→1
score_AP  = clip( (0.30 - Anti_pattern_Rate) / (0.30 - 0.10), 0, 1 )  # 30%→0, 10%→1
score_QD  = clip( (Question_Density - 0.20) / (0.40 - 0.20), 0, 1 )   # 20%→0, 40%→1
score_MT  = clip( (0.35 - Mixed_Turn_Rate)  / (0.35 - 0.15), 0, 1 )   # 35%→0, 15%→1

LayerA_normalized = 0.35·score_CR + 0.25·score_AP + 0.25·score_QD + 0.15·score_MT
```

> KPI 4개의 가중치는 "Coaching Ratio가 가장 종합적 → 가장 높은 0.35" 가설. §7.3 재조정 대상.

## 5. Layer B — 출력 품질 검증 (#3 · #4 산출물)

> **단위**: 세션 1회당 1개 점수.
> **도구**: 결정적 코드 검증 (AI 호출 없음). 03/04/05 명세서의 §6 검증 룰을 그대로 인용.
> **가장 중요한 가드레일**: #4 의 `source_seed_id` 시드 풀 위반율 — 자유 생성 차단의 핵심.

### 5.1 #3 역량 5장 카드 검증 (04.competency_analysis §6)

**Step 1 (결정적, 코드)** — 04 명세서 §6.1 에서 정의된 룰. 모든 항목이 0/1 체크.

| 검증 항목 | 룰 | 통과 시 | 위반 시 |
|---|---|---:|---|
| 카드 개수 | 정확히 5개 | 1 | 코드 버그 — 세션 무효 처리 |
| `slot` 분포 | `{1,2,3,4,5}` 일치 | 1 | 세션 무효 |
| `code` 중복 없음 | distinct == 5 | 1 | 세션 무효 |
| `match_score` 범위 | 0~5 정수 | 1 | 세션 무효 |
| `badge` enum | 3종 중 하나 | 1 | 세션 무효 |
| 슬롯 1~3 badge | 모두 `strength_match` | 1 | 세션 무효 |
| 슬롯 4 badge | `user_interest` 또는 fallback `strength_match` | 1 | 세션 무효 |
| 슬롯 5 badge | `growth_potential` 또는 fallback `strength_match` | 1 | 세션 무효 |

**Step 2 (AI personalized_text)** — 04 명세서 §6.2.

| 검증 항목 | 룰 | 통과 시 | 위반 시 |
|---|---|---:|---|
| JSON 파싱 | 유효 JSON | 1 | 재시도 카운트 +1, 통과시 0.5 |
| `cards` 키 + 5개 | required | 1 | 동일 |
| `slot` 분포 `{1..5}` | 일치 | 1 | 동일 |
| `personalized_text` 길이 | 60~200자 (각 카드) | 1 | 동일 |

**#3 점수화**:

```
S3_step1 = (8개 항목 평균, 0~1)              # 정상 케이스에서 항상 1.0
S3_step2 = (4개 항목 평균, 0~1)              # 재시도 1회 = 0.5, 2회+ = 0
S3_retry_penalty = max(0, 1 - 0.3·retry_count)   # 재시도 1회 → 0.7, 2회 → 0.4
S3_fallback_penalty = 0.5 if step2 fallback 발동 else 1.0
                                              # AI 카드 문구 정적 fallback (04 §6.3) 발동 시

score_3 = S3_step1 · S3_step2 · S3_retry_penalty · S3_fallback_penalty
```

> Step 1은 결정적 코드라 실패 = 코드 버그 = 세션 무효. 실질적 변별은 Step 2의 재시도·fallback에서 일어남.

### 5.2 #4 액션아이템 검증 (05_action_item §6) — **가중치 최대**

**5.2.1 출력 형식 검증** (05 §6.1) — 4개 항목.

| 검증 항목 | 룰 | 통과 시 | 위반 시 |
|---|---|---:|---|
| JSON 파싱 + 스키마 | `actions` 3~5개, 4키 모두 존재 | 1 | 재시도 |
| `title` 길이 | 8~60자 | 1 | 재시도 |
| `description` 길이 | 20~240자 | 1 | 재시도 |
| `tags` 개수 | 2~4개 | 1 | 재시도 |

**5.2.2 시드 풀 검증** (05 §6.2) — **이 명세서의 핵심 가드레일**.

05 §6.2 의 룰을 그대로 인용:
1. `source_seed_id`는 이번 호출에서 AI에게 노출된 6개 시드(주력 1 + 보조 1 + 참고 4) 중 하나여야 한다.
2. 노출되지 않은 다른 역량의 시드 ID(예: `I-1-junior-1`)를 적어내도 거부.
3. 시드 풀에 없는 가짜 ID(예: `T-1-junior-9`)를 만들어내도 거부.

```
# 시드 풀 위반율 — Layer B 의 가장 중요한 지표
violation_rate_seed = (위반 액션 수) / (전체 액션 수)
score_seed = (1 - violation_rate_seed)²    # 비선형: 1건 위반도 강하게 감점
```

**비선형 제곱항을 쓰는 이유**: 시드 풀 위반은 "자유 생성 차단" 약속을 깨는 행위. 5건 중 1건(20%) 위반 = 0.64점, 2건(40%) = 0.36점. 선형 감점보다 강하게.

**5.2.3 재시도/fallback** (05 §6.4).

```
S4_format = (4개 항목 평균, 0~1)
S4_retry_penalty = max(0, 1 - 0.3·retry_count)
S4_fallback_penalty = 0.3 if deterministic fallback 발동 else 1.0
                      # 결정적 fallback (강점 톤 미적용 plain) = 강한 감점

score_4 = score_seed · S4_format · S4_retry_penalty · S4_fallback_penalty
```

> **변별력 보강 (§우려 1 반영)**: 03/04/05 명세서가 모두 "재시도 → fallback"으로 schema-valid를 보장하므로 형식 검증만 보면 점수가 1.0에 수렴한다. 따라서 Layer B는 `retry_count`, `fallback 발동 여부`를 **직접 감점 항목**으로 흡수한다. 명세서가 fallback으로 "구원"한 경우, Layer B는 그것을 "실패한 것"으로 본다.

### 5.3 LayerB_normalized 환산

```
LayerB_normalized = 0.30·score_3 + 0.70·score_4
```

> #4 가중치 0.70 — 시드 풀 위반이 제품의 핵심 약속("자유 생성 차단")과 직결되므로 #3보다 크게.

## 6. Layer C — 페르소나 자기평가

> **단위**: 세션 1회당 1개 점수.
> **도구**: 페르소나-LLM의 자가 채점 (cross-vendor 원칙 필수).
> **WhyTree 차용**: 사용자가 세션 전체에서 느낀 가치를 4축으로 본다.

### 6.1 채점 4축 (1~10 정수)

| 축 | 정의 | 측정 의도 |
|---|---|---|
| `overall_value` | 세션 전체가 유용했는가 | 종합 만족 |
| `insight_novelty` | 스스로 몰랐던 점을 새로 발견했는가 | 코칭 본질 (자기 발견) |
| `emotional_safety` | 안전하게 말할 수 있었는가 | ICF 원칙 충실도 |
| `desire_to_return` | 다음 세션도 쓰고 싶은가 | 제품 적합도 |

### 6.2 채점 프로토콜 (cross-vendor 필수)

**§우려 4 반영**: Layer A 와 동일하게 **생성 모델 ≠ 채점 모델** 원칙을 명시. 페르소나가 Claude Sonnet으로 발화했다면 Layer C 자가채점은 GPT-4o 또는 Gemini로 수행. 같은 벤더면 self-judging bias로 점수가 후하게 나옴.

**입력**: 세션 전체 트랜스크립트 (인터뷰 대화 + #3 카드 5장 + #4 액션 3~5건) + 페르소나 프로파일.

**채점 프롬프트** (초안):

```text
당신은 아래 페르소나의 입장에서 방금 끝난 AI 코칭 세션을 회고합니다.
페르소나의 성격·가치관·말투에 충실하게, 1~10 정수로 다음 4축을 채점하세요.
숫자 외 텍스트는 rationale 필드에만 적습니다.

[페르소나]
{persona_profile}

[세션 트랜스크립트]
{transcript}

[채점 축]
- overall_value:     세션 전체가 나에게 유용했는가
- insight_novelty:   내가 스스로 몰랐던 점을 새로 발견했는가
- emotional_safety:  안전하게 말할 수 있었는가
- desire_to_return:  다음 세션도 쓰고 싶은가

JSON으로만 답하세요:
{
  "overall_value":    1~10,
  "insight_novelty":  1~10,
  "emotional_safety": 1~10,
  "desire_to_return": 1~10,
  "rationale": "한국어 2~3문장"
}
```

**온도**: 0.3 (페르소나의 자연스러운 변동 허용. Layer A의 채점 0과 다름).

### 6.3 LayerC_normalized 환산

```
LayerC_normalized = mean(4축) / 10        # 단순 평균 후 0~1 정규화
```

> 4축 가중치를 두지 않는 이유: 페르소나마다 중시하는 축이 다르고, baseline 측정 전에는 자의적 가중을 피한다.

---

## 7. Composite Score & 종료 조건

### 7.1 환산식

```
session_score = 10 × (0.5·LayerA_normalized
                    + 0.3·LayerB_normalized
                    + 0.2·LayerC_normalized)
```

**가중치 근거 (가설)**:
- 0.5 (Layer A) — 코칭 원칙 충실도가 제품의 약속. 가장 큰 비중.
- 0.3 (Layer B) — 산출물 안정성. 시드 풀 위반은 제품 약속 위반이지만 fallback이 있어 변별이 약함.
- 0.2 (Layer C) — 페르소나 자가평가는 신호로는 강하나, 자기 채점 bias가 남아 보수적으로.

### 7.2 종료 조건 (ralph-loop stop criteria)

루프는 다음 두 조건을 **모두** 만족할 때 종료:

1. **평균 조건**: 34 페르소나 평균 `session_score ≥ 9.0`
2. **비정형 안전망**: 비정형 페르소나 7명이 **모두** `session_score ≥ 8.0`

> 비정형 7명은 평균에 가려질 위험이 큰 코너 케이스(짧은 답·영어 혼용·정서적 톤 등). 이들의 최저선을 별도로 잡지 않으면 "평균은 좋은데 7명에 무너지는" 시스템이 통과해버린다.

### 7.3 v2 알려진 한계 (§우려 2·3 반영)

> 이 박스는 학기말 발표용으로도 유지. 가설을 명시하는 게 더 정직함.

**한계 ①: 단위 이질성 — 정규화 곡선은 자의적이다**
- Layer A는 턴 단위 비율(0~1), Layer B는 세션 단위 룰 위반율(0~1, 비선형), Layer C는 1~10 자가점수.
- §4.1 의 선형 매핑(예: Coaching Ratio 50%→0, 80%→1)은 합의된 baseline이 아니라 가설.
- 곡선이 다르면 같은 시스템의 LayerA_normalized 점수가 달라진다.
- **대응**: baseline 50개 대화 측정 후 §4.1 선형 구간을 1회 재조정.

**한계 ②: 가중치(0.5/0.3/0.2)와 임계값(9.0/8.0)은 baseline 전엔 검증 불가**
- ralph-loop이 9.0을 못 넘기면 "프롬프트가 부족"인지 "가중치·임계값이 빡센지" 분리되지 않는다.
- **대응**: baseline 측정(W6) 직후 §7.1 가중치와 §7.2 임계값을 1회 재조정. 그 이후로는 동결.
- **재조정 룰**: baseline 평균이 5점대면 가중치·곡선을 손대고, 8점대면 임계값을 손대고, 6~7점이면 그대로 가설 유지.

**한계 ③: Layer B 변별력의 비대칭**
- 03/04/05 명세서가 "재시도 → fallback"으로 schema-valid를 보장 → 형식 검증만 보면 1.0 수렴.
- §5 에서 `retry_count`와 `fallback 발동`을 직접 감점 항목으로 흡수했지만, 이는 명세서 fallback 룰의 존재를 "실패 신호"로 재해석한 것.
- 명세서 §6 가 바뀌면 Layer B 점수 의미도 바뀐다 — **명세서와 평가 룰북의 결합도가 높다**는 점을 의식할 것.

## 8. 재시도/Fallback과 점수의 관계

> 03/04/05 명세서의 재시도·fallback 룰이 Layer B 점수에 어떻게 흡수되는지의 매핑표. §5 의 점수식을 한눈에 보기 위함.

| 명세서 | 항목 | 명세서 §위치 | Layer B 점수 반영 |
|---|---|---|---|
| 03 인터뷰 | JSON 파싱 실패 → 재시도 2회 | §6.2 | Layer A 범위 (인터뷰 트랜스크립트 추출은 Layer B 대상 아님) |
| 03 인터뷰 | 2회 실패 → 빈 key_insights fallback | §6.2 | (Layer B 비대상). 이후 #3에서 mentioned 빈 배열 fallback (04 §6.4) → score_3 에 반영 |
| 04 #3 Step1 | 코드 검증 위반 | §6.1 | `score_3 의 S3_step1 = 0` → 세션 무효 |
| 04 #3 Step2 | JSON 파싱·길이 위반 → 재시도 | §6.2~6.3 | `S3_retry_penalty` 에 흡수 |
| 04 #3 Step2 | 2회 실패 → 정적 fallback 텍스트 | §6.3 | `S3_fallback_penalty = 0.5` |
| 04 #3 Step1 | 슬롯 4 mentioned 빈/중복 → strength_match fallback | §6.4 | 정상 동작으로 간주 (감점 없음, 명세서가 의도한 fallback) |
| 04 #3 Step1 | 슬롯 5 도메인 fallback | §6.4 | 정상 동작으로 간주 (감점 없음) |
| 05 #4 | 형식 검증 위반 → 재시도 | §6.1, §6.4 | `S4_retry_penalty` 에 흡수 |
| 05 #4 | 시드 풀 위반 → 재시도 | §6.2, §6.4 | `score_seed = (1 - violation_rate)²` 에 반영 (가장 중요) |
| 05 #4 | 2회 실패 → 결정적 fallback (plain text 액션) | §6.4 | `S4_fallback_penalty = 0.3` (강한 감점) |
| 05 #4 | `tags` 행동동사 종결 등 의미 검증 | §6.3 | 경고 로그만, 점수 미반영 (v2 범위 외) |

**핵심 원칙 두 가지**:
1. **명세서가 "정상 동작"으로 의도한 fallback**(예: 04 §6.4 슬롯 4 mentioned 빈 배열) — 감점 없음.
2. **명세서가 "실패 구원"으로 의도한 fallback**(예: 04 §6.3 정적 텍스트, 05 §6.4 결정적 fallback) — Layer B 감점.

이 구분이 §우려 1(변별력)의 해소 장치다.

## 11. 한계와 주의사항 (v0.1 원본 + v2 보강)

1. **LLM-as-judge bias** — 같은 회사 모델끼리 채점하면 후하게 줍니다. **Layer A와 Layer C 모두 cross-vendor 필수**. 정기적으로 인간 라벨과 kappa를 재측정.

2. **한국어 코칭 도메인 검증 부재** — 영어권 ICF·심리치료 연구의 루브릭을 차용했으나, 한국어 대화의 미묘한 어감(예: 완곡한 조언)은 별도 보정 필요. 학기 초 30~50개 대화를 팀 내부에서 직접 라벨링해 한국어 적응 가이드라인을 만들 것.

3. **카테고리의 양자택일 한계** — "조언처럼 들리는 질문" 같은 경계 사례. 부 카테고리 라벨을 허용해 일부 완화했지만 완벽하지 않음.

4. **단기 지표 ≠ 장기 효과** — Coaching Ratio가 높다고 사용자에게 실제 도움이 됐다는 보장은 없습니다. v2 의 Layer C 자가채점이 이 갭을 일부 메우지만, 페르소나 시뮬레이션은 실사용자가 아님.

5. **윤리 / 프라이버시** — 채점에 쓰이는 대화 샘플은 사용자 동의 범위 내에서만 사용. 외부 LLM API에 채점을 맡길 경우, 학습 제외(zero-retention) 옵션을 반드시 설정.

6. **(v2 신규) 명세서-룰북 결합도** — Layer B 점수는 03/04/05 §6 의 fallback 룰 정의에 강하게 의존. 명세서 §6 이 바뀌면 §5·§8 도 함께 갱신해야 함.
