# 커리어 인터뷰 종료 재설계 — 팀 합의 문서

> 목적: 커리어 인터뷰의 **종료 방식**을 팀원과 합의하기 위한 문서.
> 대상 독자: PO/기획, 프론트, 백엔드/DB, 디자이너.
> 상태: **합의 대기** (아래 "합의가 필요한 항목" 참고)

---

## 1. 배경 — 무엇이 문제였나

기존 커리어 인터뷰는 **사용자 메시지 30턴**에 도달하면 시스템이 인터뷰를 **강제로 완료 처리**했다.

- 사용자가 한창 이야기하는 중에 입력창이 사라지고 "진단 완료하기" 버튼만 남음 → **갑작스러운 컷** 경험
- 반대로, 더 이야기하고 싶은 사용자는 30턴에서 막혀버림
- 코치가 자연스럽게 마무리하지 못한 채 잘리면, 대화 arc가 미완결인 상태로 역량 도출이 진행됨

## 2. 핵심 설계 결정 (이번 변경의 본질)

### 2-1. 종료 기준 = "턴 숫자"가 아니라 "목표 완결"
인터뷰의 목적은 **커리어 방향을 잡고 역량 도출에 충분한 재료를 얻는 것**. 따라서 종료 기준도 거기서 나온다.

> **목표 완결 조건 (turn 무관):**
> ① 합의 주제(agreed_focus)에 대해 사용자가 **방향·통찰**을 얻음
> ② 가장 작은 **다음 한 발(next action)**이 구체화됨
>
> → 둘 다 차면 코치가 자연스럽게 마무리. 안 차면 턴 수와 무관하게 계속.

### 2-2. 시스템의 "고정 턴 강제 종료"는 제거
- 완료(`isInterviewComplete`)는 **오직 코치의 자연 종료 발화**(종료 키워드)로만 일어난다.
- turn_count는 더 이상 완료 신호가 아니다.

### 2-3. 긴 세션은 "프롬프트로 유도"해서 닫는다 (끊지 않음)
- turn_count 63 이후부터, 시스템이 매 턴 프롬프트에 **강한 마무리 유도 지시(forceClose)** 를 주입 → 코치가 스스로 따뜻하게 마무리하도록.
- 끊는 게 아니라 **유도**. 코치가 안 닫으면 세션은 계속됨(관측 로그만 남김).

### 2-4. "목표 충족 후에도 계속하고 싶을 때" → (나) 방식
선택지 두 개 중 **(나) 채택**:
- (가) 선택지를 주고 원하면 계속 — ❌ 미채택
- **(나) "충분하다"며 부드럽지만 분명히 마무리로 유도** — ✅ 채택

근거: 이 인터뷰는 **1회 온보딩 세션 = 결과 1개**이고, **더 깊은 탐색은 이후 주간 회고 코칭에서 계속**된다. 따라서:
> "오늘 다룬 건 시작점이고, 더 깊은 건 주간 회고에서 이어가요. 오늘은 여기서 정리할게요."
> → 닫는 게 "끝"이 아니라 "다음으로 이어짐". 사용자가 손해 본다는 느낌 없이 받아들임. 무한 세션도 자연히 방지.

### 2-5. "온보딩은 충분히면 됨 — 완벽히가 아님"
오늘 모든 걸 다 다루려 하지 않는다. 역량 도출에 충분한 재료가 모이면 닫는 게 옳다.

### 2-6. 흐름을 끊지 않기 위한 "신호 기반" 판단
점검/마무리는 **턴 숫자가 아니라 사용자 발화의 관찰 신호**로만 작동:
- 🟢 **일단락 신호** (점검/마무리 시도 가능): 짧은 수긍("네, 맞아요"), 스스로 결론·통찰 발화, 답을 다 하고 새 정보 없음
- 🔴 **진행 중 신호** (보류): 발화가 펼쳐지는 중, "근데/그래서…"로 이어짐, 새 사건·인물 꺼냄, 되묻기/감정 고조

### 2-7. 합의 주제 앵커링 — 상시 능동 + 닻 갱신
- 코치는 agreed_focus를 **매 턴 상시로 의식**(삼천포 방지).
- 단, **삼천포(무관한 곁가지)** 와 **생산적 심화(더 진짜인 주제 발견)** 를 구분 → 후자는 따라가고 **agreed_focus를 새로 미러링해 갱신**. (초기 가설에 60턴을 가두지 않음)

### 2-8. 사용자 종료 버튼 추가
사용자가 원하면 언제든 직접 종료할 수 있는 **"인터뷰 종료하기"** 버튼 추가. 상한 제거의 짝(통제감 부여).

## 3. 사용자 "인터뷰 종료하기" 버튼 — UX 결정안

| 항목 | 결정 |
|---|---|
| **라벨** | "인터뷰 종료하기" (확정) |
| **위치** | 헤더 우상단 텍스트 버튼 (현재 대칭용 빈 공간 자리) |
| **스타일** | 고스트/회색 텍스트. primary(파랑)는 전송·"진단 완료하기"에 양보 |
| **노출 시점** | 1턴부터 항상 노출 (통제감), 단 다이얼로그가 상황 적응 |
| **확인 다이얼로그** | 있음 (실수 탭 방지 + "종료=결과 생성" 안내) |
| **조기 종료 기준** | **탐색(exploration) 진입 전 = 조기** → 경고 변형 카피 |
| **종료 후 흐름** | **1단계**: 확인 → 곧장 finalize → 분석 로딩 → 결과 |
| **finalizing 중** | 버튼 숨김/비활성 |

### 다이얼로그 카피
- **일반(합의 후):** "지금 종료하면 지금까지 나눈 내용으로 **커리어 결과를 만들어 드려요.** 종료할까요?"
  버튼: **[종료하고 결과 보기]** / [계속하기]
- **조기(탐색 진입 전):** "아직 충분히 이야기 나누지 못했어요. 지금 종료하면 결과가 간단할 수 있어요."
  버튼: **[계속하기]**(강조) / [그래도 종료]

### UX 주의
- 좌상단 `←`(페이지 이탈, 결과 생성 안 함) 과 우상단 "인터뷰 종료하기"(마치고 결과 생성)의 **역할 차이**를 다이얼로그 카피로 분명히 한다.
- 모바일 폭(~430px)에서 헤더가 빠듯하면 라벨을 "종료"로 축약 가능.

## 4. 역할별 작업

### 프론트엔드
- `web/app/api/career-interview/chat/route.ts`: 고정 턴 강제 종료 제거, forceClose 주입 (※ 본 클론에는 적용됨, 정식 레포 반영 필요)
- `web/lib/prompts/career-interview.ts`: §11~§14 프롬프트 규칙 (※ 동일)
- `web/app/onboarding/career-interview/page.tsx`: **"인터뷰 종료하기" 버튼 + 확인 다이얼로그 + 1단계 finalize** (신규)

### 백엔드/DB 설계자
- **기능 필수: 없음.** finalize INSERT는 종료 방식과 무관하게 동작.
- **선택(권장):** `career_interview_results`에 nullable `end_reason` 컬럼 추가 (`coach_natural` / `user_button` / `user_keyword`) — 종료 방식 분석용.
- 확인: `/api/career-interview/finalize` 가 **짧은 트랜스크립트**(조기 종료)에서도 견고하게 동작하는지.

### 디자이너
- 헤더 우상단 버튼 시각 스펙, 확인 다이얼로그(일반/조기 2종) 디자인, 모바일 폭 처리.

## 5. 합의가 필요한 항목 (의사결정 요청)

1. **조기 종료 기준**: "탐색 진입 전" 으로 충분한가? (대안: user 5턴 미만 등 턴 기준 병행)
2. **종료 후 흐름**: 1단계(곧장 finalize)로 확정? (대안: 2단계 — 완료 화면에서 "진단 완료하기" 재확인)
3. **DB `end_reason` 컬럼** 추가 여부.
4. **헤더 라벨 길이**: "인터뷰 종료하기" 유지 vs "종료" 축약.

## 6. 리스크 & 완화

| 리스크 | 완화 |
|---|---|
| 코치가 forceClose를 무시하고 안 닫음 → 무한 세션 | 관측 로그(70턴~) + "온보딩은 충분히면 됨" 프롬프트 원칙 + 사용자 종료 버튼 |
| 조기 종료 → 역량 도출 부실 | 조기 변형 다이얼로그로 "계속하기" 유도 + finalize 견고성 확인 |
| 목표 완결 판단을 모델이 잘못함 | 🟢/🔴 신호 + §12 방향 점검(30~35)으로 중간 재정렬 |
| 무한정 길어져 컨텍스트/비용 증가 | 1세션=결과 1개 원칙으로 회고 세션에 이월 |
