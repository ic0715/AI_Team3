## 1. Purpose

**터치포인트**: AI 연동 #2 — 커리어 인터뷰 (대화형)

**입력**: 사용자의 Top 5 강점 분석 결과(`strength_analyses.strengths`)와 클라이언트가 슬라이싱한 강점 페어 20문장.

**출력**:
- `career_interview_results.key_insights` (신규 4키 + 기존 7키 optional + `mentioned_competencies`)
- `career_interview_results.session_duration_choice` (별도 컬럼, enum: `short`/`medium`/`long`)
- `career_interview_results.ai_summary` (한 줄 요약 60자 이내)

**역할**:
- 단일 오프닝 질문("지금 갖고 있는 가장 큰 커리어 고민이 뭔가요?")으로 시작, ICF MCC 8역량 기반 자유 탐색.
- Phase 2에서 사용자와 *오늘 다루기로 한 것*에 대해 명시적 합의 형성.
- 표면→진짜 이슈 시그널 감지 시 합의 재조정 *제안*.
- 정서 위기 신호 감지 시 단계별 redirect.
- 종료 시 대화 전체를 분석해 구조화된 JSON으로 출력.

> 이 단계에서 `recommended_competencies`는 채우지 않는다 (#3에서 별도 처리).

## 2. Inputs

### 2.1 DB Inputs

**조회 대상**: `strength_analyses` 테이블 — 사용자의 최신 Top 5 강점.

```sql
SELECT strengths
  FROM strength_analyses
 WHERE user_id   = :current_user_id
   AND is_latest = true
 LIMIT 1;
```

**기대 형식**: `strengths` JSONB 배열 5개 원소 (v0.7.1과 동일).

**보조 컨텍스트** (페르소나 미세 조정용, 선택):
- `profiles.nickname` — 인터뷰 중 호칭
- `profiles.job_field` — 사례 톤 조정
- `profiles.career_level` — junior/senior 톤 조정

### 2.2 Static Reference Inputs

**소스**: `강점코칭_테마별_조합.docx` (강점 페어 1,088문장, 양방향).

**슬라이싱 룰**: Top 5에서 C(5,2)=10페어 × 양방향 2문장 = 20문장 (v0.7.1과 동일).

**토큰 추정**: 페어 한 문장 ~50토큰 → 20문장 × 50 = **약 1,000~1,200토큰**.

**주입 위치**: System Prompt 내부 `<강점_페어_컨텍스트>` 블록.

> **품질 기법 #1 — Prompt Caching**: 페어 컨텍스트 블록에 Anthropic API의 `cache_control: {"type": "ephemeral"}` 플래그를 적용한다. 5분간 캐시 유지로 인터뷰 진행 중 입력 비용 ~90% 절감.

> 페어 원문은 `.gitignore`로 비공개. 클라이언트가 빌드 시 번들링하고 인터뷰 시작 시점에 슬라이싱하여 프롬프트에 주입한다.

## 3. Persona & Voice

**페르소나**: ICF MCC 수준의 커리어 코치.

**핵심 자세**:
- 답을 주지 않고 사용자가 스스로 표현하도록 돕는다.
- 짧고 또렷한 한 문장 질문. 두 개의 질문을 한 번에 하지 않는다.
- 사용자의 답을 그대로 되받아 인용하며 다음 질문으로 이어간다 (echo-back).
- 강점 페어 컨텍스트는 **암묵적으로** 사용한다. "당신은 X+Y 페어니까…" 같은 진단 어투 금지.
- 패턴 A~H(시스템 프롬프트 참조)는 **결의 틀**이며, 매번 사용자의 언어·맥락에 맞춰 변주한다.

**톤**:
- 존댓말, 따뜻하지만 정중. 과한 친밀감·이모지·감탄사 자제.
- 한 응답 ≤ 3문장. 사용자가 길게 답하면 코치는 더 짧게 받는다.

**금지 표현**:
- "AI로서 말씀드리면…" / "분석 결과…" / "데이터에 따르면…"
- "정답은 ~입니다" / "~해야 합니다" / "~가 맞습니다"
- 사용자 답을 평가하는 표현 ("훌륭하시네요", "대단합니다")
- 사용자의 강점을 직접 호명하는 표현 ("당신의 분석 강점이…")

## 4. Logic / Pipeline

### 4.1 인터뷰 흐름 — 4 Phase 자유 흐름

대화는 **고정 질문 없이** 4-Phase 구조로 흐른다. 각 Phase 사이 전환은 AI가 사용자 응답을 보고 자율 판단.

```text
[ 시작 ]
  System Prompt 주입 (강점 5 + 페어 20문장, 캐시됨)
  Running State 초기값: { phase: "opening", agreed_focus: "", turn_count: 0, session_duration: "medium" }
                            ↓
┌── Phase 1: Opening (1~3턴) ─────────────────────────────┐
│  코치 1턴: 인사 + "중간에 멈춰도 된다" 안내 + 시간 질문   │
│  사용자 2턴: 시간 자연어 응답                              │
│  코치 3턴: 시간 반영 + 단일 오프닝 질문                    │
│           "지금 갖고 있는 가장 큰 커리어 고민이 뭔가요?"   │
└─────────────────────────────────────────────────────────┘
                            ↓
┌── Phase 2: Echo & Agreement (2~4턴) ────────────────────┐
│  사용자: 고민 표현 (presenting_issue 후보)                 │
│  코치: B 패턴 echo-back (한 번 펴기)                       │
│  사용자: 더 설명                                            │
│  코치: A 패턴 합의 질문                                     │
│  사용자: 합의 응답 (또는 "잘 모르겠어요" → E 패턴)         │
│  코치: 합의 미러링 (agreed_focus 확정)                      │
└─────────────────────────────────────────────────────────┘
                            ↓
┌── Phase 3: Exploration (시간 대부분, 자유) ──────────────┐
│  합의된 목표에 비춰 AI 자유 탐색                            │
│  - B, C, D 패턴 활용                                        │
│  - 페어 컨텍스트 20문장은 *암묵* 단서로만 활용             │
│  - 표면→진짜 이슈 시그널 감지 시 F 패턴으로 재조정 *제안*   │
│  - 정서 위기 신호 감지 시 단계별 redirect                   │
└─────────────────────────────────────────────────────────┘
                            ↓
┌── Phase 4: Closing (1~2턴) ─────────────────────────────┐
│  코치: G 패턴 ("오늘 어떤 게 손에 잡히셨어요?")            │
│  사용자: takeaway 표현 (user_takeaway 후보)                │
│  코치: H 패턴 종료 발화 → 클라이언트 키워드 감지하여 종료  │
└─────────────────────────────────────────────────────────┘
                            ↓
[ Extraction (코드, AI 호출 1회, Extended Thinking + Temperature 0) ]
  대화 전체 → 신규 4키 + 기존 7키(optional) + mentioned_competencies + session_duration_choice + ai_summary
                            ↓
[ DB INSERT — career_interview_results 새 row ]
```

### 4.2 시간 정보 처리 (Phase 1 → DB)

코치 첫 발화에서 자연어로 시간을 묻고, 사용자 응답을 AI·클라이언트가 함께 해석.

| 사용자 응답 패턴 | 내부 깊이 레벨 | DB 저장값 | 코치 반영 멘트 |
|---|---|---|---|
| "15분", "20분", "짧게", "급해요" | 짧게 | `short` | "○분이면 한 가지 핵심을 또렷하게 만들어볼 수 있어요" |
| "30분", "40분", "보통" | 보통 | `medium` | "○분 동안 한 가지 주제를 충분히 들여다볼 수 있겠네요" |
| "1시간", "충분히", "시간 많아요" | 깊이 | `long` | "한 가지 주제를 깊이 있게 다뤄볼 수 있는 시간이에요" |
| 시간 안 밝힘, 모호 | 보통 (기본값) | `medium` | 시간 언급 없이 "그럼 시작해볼게요" |

> 저장값은 추출 단계(§4.2.B)에서 AI가 JSON 키로 출력한다. 진행 중에는 Running State에 함께 주입돼 깊이 판단에 활용된다.

### 4.3 종료 감지 (클라이언트 측 텍스트 매칭, 3 paths)

**Path A — 자연 종료**
- 트리거: 코치 발화에 H 패턴 키워드 포함 (`["오늘 인터뷰는 여기서", "오늘은 여기까지", "여기서 마무리할게요"]`)
- 처리: 클라이언트가 키워드 감지 → 추출 단계로 전환

**Path B — 사용자 주도 종료**
- 트리거: 사용자 발화에 종료 의도 표현 (`["여기까지 할게요", "그만하고 싶어요", "이제 됐어요", "오늘은 여기까지"]`)
- 처리: 클라이언트가 키워드 감지 → 추출 단계로 전환

**Path C — 정서 위기 🔴 redirect**
- 트리거: 🔴 키워드 감지 → AI가 redirect 멘트 출력 (§4.5 참조)
- 처리: 클라이언트가 redirect 발화 종료 후 자동 종료. **추출 단계 스킵**. 세션 메타만 저장 (`key_insights = NULL`, `session_duration_choice = 'medium'` 기본값, `ai_summary = "정서 위기 가드레일 작동으로 인터뷰 중단"`)

### 4.4 Running State Injection (품질 기법 #2)

매 턴 클라이언트는 user 메시지 앞에 다음 블록을 자동 주입한다. AI는 이를 통해 현재 합의·페이즈·시간을 매 턴 명시적으로 인식한다.

```
<현재_상태>
phase: opening | echo_agreement | exploration | closing
agreed_focus: "{Phase 2에서 합의된 한 줄, 미합의 시 빈 문자열}"
turn_count: {정수}
session_duration: short | medium | long
</현재_상태>
```

**캐시 경계**: 시스템 프롬프트의 정적 부분(원칙·패턴·정서 위기·페어 컨텍스트)은 `cache_control` 적용 → 캐시. `<현재_상태>` 블록과 누적 대화는 매 턴 동적이므로 캐시 경계 밖.

### 4.5 정서 위기 가드레일 (3단계)

#### 🔴 즉시 redirect (안전 영역 — 코칭 즉시 중단)

**키워드**
- 자해·자살 직접 언급: `["죽고 싶다", "사라지고 싶다", "끝내고 싶다", "이 세상에서 없어졌으면"]`
- 자해 행동 언급: `["스스로 다치게 한다"]`
- 타인 가해 의사: `["누구를 해치고 싶다"]`

**대응 멘트** (AI가 출력 → 클라이언트가 Path C로 종료)

```
지금 말씀해주신 건 제가 다룰 수 있는 영역을 넘어서는 무게가 있어요.
이런 마음은 혼자 견디지 않으셔도 돼요.

지금 바로 연결되는 자원이 있어요:
• 자살예방상담전화 1393 (24시간, 무료)
• 정신건강 위기상담전화 1577-0199 (24시간)

오늘 인터뷰는 여기서 마무리하고, 위 번호로 연결해보시는 걸 권하고 싶어요.
괜찮으실 때 다시 만나뵐게요.
```

#### 🟠 부드러운 redirect (임상 영역 시그널 — 외부 자원 안내 + 사용자 선택)

**키워드**
- 지속적 수면 문제: "잠을 못 자요", "새벽에 자꾸 깨요" (지속성 표현과 함께)
- 식욕 변화: "밥이 안 들어가요", "토할 것 같아요"
- 강한 무력감 지속: "아무것도 못 하겠어요", "침대에서 못 일어나요"
- 공황·불안 발작 언급: "숨이 안 쉬어져요", "발작이 와요"
- 정신과 약물 언급 (현재 복용 중): "약을 먹고 있어요", "정신과 다녀요"

**대응 멘트**

```
○○님, 말씀해주신 게 마음에 남아요. 이건 커리어 고민과 함께 흐르고 있긴
하지만, 좀 더 전문적인 도움이 필요한 결의 이야기인 것 같아요.

이 부분은 정신건강 전문가와 이야기해보시면 더 깊은 도움을 받으실 수 있어요.
지역 정신건강복지센터(전국 244곳)나 동네 정신건강의학과를 한 번 알아보시는
걸 권해드리고 싶어요.

오늘 인터뷰는 ○○님이 편하신 만큼만 이어가셔도 좋고, 여기서 멈추셔도 좋아요.
어떻게 하고 싶으세요?
```

→ 🟠에서는 사용자에게 선택권을 줌. 강제 종료 안 함.

#### 🟡 주의 관찰 (감정 강도 높음 — 코칭 계속, 페이스 조절)

**키워드**
- "매일 출근길에 눈물이 나요", "회사 가는 게 너무 무서워요"
- "최근에 자주 울어요"
- 단발성 무력감 표현 ("오늘 너무 지쳤어요")

**대응**: redirect 대상이 아님. B 패턴으로 감정을 받아주되 그 감정을 코칭 합의의 출발점으로 자연스럽게 가져감 ("그 무게가 어떤 모습으로 느껴지세요?").

### 4.6 AI Prompt Template

#### 4.6.A 인터뷰 진행용 System Prompt (v2)

```text
당신은 ICF MCC 수준의 커리어 코치입니다.
한국어로, 존댓말로, 따뜻하지만 정중하게 대화합니다.

━━━━━━ [원칙] ━━━━━━ (정적, 캐시됨)
- 한 번에 한 가지만 묻습니다. 답을 주지 않고 사용자가 스스로 표현하도록 돕습니다.
- 사용자의 답에서 핵심 단어를 그대로 되받아 다음 질문으로 잇습니다.
- 응답은 최대 3문장. 사용자가 길게 답할수록 코치는 더 짧게 받습니다.
- 사용자의 강점을 직접 호명하지 마세요 ("당신의 ○○ 강점이…" 금지).
- "AI로서", "분석 결과", "데이터에 따르면" 같은 표현 금지.
- 평가하지 마세요 ("훌륭하시네요", "대단합니다" 금지).
- 패턴 A~H는 결의 틀입니다. 예시 문장을 그대로 복붙하지 말고 매번 사용자의 언어로 변주하세요.

━━━━━━ [인터뷰 구조: 4 Phase 자유 흐름] ━━━━━━ (정적, 캐시됨)
```

- 60자 이내 한 줄 요약. 빈 문자열 불가. fallback은 §6.

## 6. Validation & Fallback

### 6.1 출력 검증

**파싱 단계**:

```python
# 1) 응답 분리
parts = response_text.split("\n---SUMMARY---\n")
if len(parts) != 2:
    raise ParseError("SUMMARY 구분자 누락")

extraction_str, ai_summary = parts[0].strip(), parts[1].strip()

# 2) JSON 파싱
extraction = json.loads(extraction_str)

# 3) 스키마 검증
validate(extraction, EXTRACTION_SCHEMA_V2)

# 4) session_duration_choice enum 체크
assert extraction["session_duration_choice"] in ("short", "medium", "long")

# 5) ai_summary 길이
assert 1 <= len(ai_summary) <= 80
```

**검증 룰**:

| 검증 항목 | 룰 | 위반 시 |
| --- | --- | --- |
| `---SUMMARY---` 구분자 | 정확히 1번 등장 | 재시도 |
| JSON 파싱 | 유효한 JSON | 재시도 |
| `presenting_issue`/`agreed_focus`/`user_takeaway`/`session_duration_choice`/`mentioned_competencies` 키 존재 | required 키 체크 | 재시도 |
| `session_duration_choice` enum | `short`/`medium`/`long` 중 하나 | `medium`으로 강제 |
| `mentioned_competencies` enum | 12역량 코드 외 값 거부 | 해당 항목 제거 후 진행 |
| `mentioned_competencies` 길이 | 0~3개 | 4개 이상이면 앞 3개만 |
| `values` 길이 (legacy) | 0~5개 | 6개 이상이면 앞 5개만 |
| 각 텍스트 키 길이 | 0~500자 (또는 legacy 400자) | 초과 시 자르기 |
| `ai_summary` 길이 | 1~80자 | 빈 문자열이면 fallback |

### 6.2 재시도 정책

- 재시도 트리거: JSON 파싱 실패 / 구분자 누락 / required 키 누락
- 재시도: 최대 **2회**. 같은 input·system prompt로 재호출.
- 2회 실패 시 fallback (§6.3).

### 6.3 Fallback

**기술 실패 fallback (재시도 2회 모두 실패)**:
```json
{
  "presenting_issue": "",
  "agreed_focus": "",
  "agreement_evolution": "",
  "user_takeaway": "",
  "session_duration_choice": "medium",
  "key_insights": {},
  "mentioned_competencies": []
}
```
`ai_summary` fallback: `"커리어 인터뷰가 완료되었습니다."` (NOT NULL 충족용).

**세션 무효 규칙 (Phase 3 화면팀 노트)**:
- `presenting_issue == "" AND agreed_focus == "" AND user_takeaway == ""` 인 row는 *유효한 인터뷰 결과 아님*. 화면팀은 이 경우 결과 화면으로 진입시키지 말고 "다시 시도하기"로 라우팅. DB row는 메타만 남기되 다음 화면 진입은 차단.

### 6.4 mentioned_competencies 추출 정책 (v0.7.1 유지)

- 균형형 추출: 명시 키워드 + 강한 동의어까지만. 약한 연상 제외.
- 0개도 정상. 약한 근거뿐이면 빈 배열 출력.
- v2에서는 명확화 질문 단계가 별도로 없음 — 인터뷰 자유 흐름 중 자연스럽게 드러난 만큼만 추출.

| # | 케이스 | 처리 |
| --- | --- | --- |
| 1 | `strength_analyses` 레코드 없음 | 클라이언트가 진입 가드. 들어왔으면 강점 분석 화면으로 강제 리다이렉트 |
| 2 | Top 5 중 일부 누락 (3~4개) | 있는 강점만으로 페어 슬라이싱 (C(n,2)) |
| 3 | 페어 슬라이스 lookup 실패 | 해당 페어 스킵. 5개 이상 실패 시 페어 컨텍스트 없이 진행 |
| 4 | 사용자가 Phase 1 시간 질문에 답 없이 바로 고민 시작 | session_duration `medium` 기본값. Phase 1을 짧게 끊고 Phase 2로 전환 |
| 5 | 사용자가 Phase 2 합의 질문에 "잘 모르겠어요" 3회 | E 패턴 fallback. 합의 형성을 유보하고 탐색 중 자연스럽게 합의. agreed_focus는 탐색 후 사용자가 또렷해진 주제로 추출 단계에서 채움 |
| 6 | 짧은 인터뷰 (Phase 1만 도달하고 이탈) | presenting_issue·agreed_focus·user_takeaway 빈 문자열 → 세션 무효 처리(§6.3) |
| 7 | Path A·Path B 동시 발생 (코치 H 패턴 발화 + 사용자 종료 키워드) | 클라이언트는 *먼저 감지된 쪽*으로 처리. 추출 입력은 동일 |
| 8 | 🟡 감정 신호 후 사용자가 명료한 합의 도달 | redirect 아님. agreed_focus를 그 감정을 출발점으로 한 표현으로 형성 (예: "출근 공포의 정체를 또렷이 하기") |
| 9 | 🟠 임상 시그널 후 사용자가 "여기서 멈출게요" | Path B로 종료. presenting_issue만 채우고 나머지 키는 ""로 출력. ai_summary는 "○○님이 휴식 선택. 외부 자원 안내 제공" 류 |
| 10 | 🔴 키워드 감지 | AI가 🔴 redirect 멘트 출력 → 클라이언트가 Path C로 종료. **추출 호출 스킵**, 메타만 INSERT (§5.1 Path C 특수 처리) |
| 11 | F 패턴 재조정 *제안*에 사용자가 "아니요, 원래 주제로 계속할게요" | agreement_evolution에 "재조정 제안 있었으나 사용자가 초기 합의 유지 선택"으로 기록. agreed_focus는 초기 합의 유지 |

## 9. Token Budget

### 9.1 인터뷰 진행 단계 (4.6.A)

**입력 토큰** (호출당):
- 시스템 프롬프트 본문 (원칙·구조·패턴 A~H·정서 위기·페어 컨텍스트): ~2,500토큰
- `<현재_상태>` 블록: ~30토큰
- 누적 대화: 평균 ~600토큰 (자유 흐름, 6~25턴 가변)

**출력 토큰**: ~50~100토큰 (코치 1턴, ≤3문장).

**호출 횟수**: 인터뷰 1회당 평균 8~20회 (session_duration_choice에 따라 가변).
- `short`: 평균 8턴
- `medium`: 평균 12턴
- `long`: 평균 20턴

**Prompt Caching 효과** (품질 기법 #1):
- 첫 호출: 정적 부분 ~2,500토큰을 캐시에 기록 (캐시 write 비용)
- 이후 호출 (5분 내): 정적 부분 **캐시 hit으로 90% 절감**
- 동적 부분(`<현재_상태>` + 누적 대화)만 새로 처리 → 매 턴 ~600~800토큰만 실제 입력

### 9.2 종료 후 추출 단계 (4.6.B)

**입력 토큰**:
- 추출 시스템 프롬프트 + 12역량 표 + fallback 룰: ~1,200토큰
- 인터뷰 대화 전체 (transcript): ~1,500~3,500토큰 (session_duration_choice에 따라)

**출력 토큰**: JSON + summary = ~400~600토큰.

**Extended Thinking 토큰** (품질 기법 #3): 호출당 추가 ~2,000~4,000 thinking 토큰 (사용자에게 노출되지 않음, 과금은 발생).

**호출 횟수**: 인터뷰 1회당 1회 (재시도 시 최대 3회).

### 9.3 호출당 비용 추정 (Sonnet 기준, 캐싱 적용)

> Anthropic Sonnet (2026) 가격 가정: 입력 $3/MTok, 캐시 hit $0.30/MTok, 출력 $15/MTok, thinking $15/MTok.

| 단계 | 입력 (실효) | 출력 | 비용 (캐시 적용) |
|---|---:|---:|---:|
| 진행 (medium, 12턴, 캐싱) | ~10,000 (캐시 hit 비중 큼) | ~700 | **~$0.025** |
| 추출 1회 (Extended Thinking 포함) | ~3,500 | ~500 + thinking ~3,000 | **~$0.06** |
| **합계 (1유저 1인터뷰)** | | | **~$0.085 (~110원)** |

> 결정문서 §9.3 추정치(~44원)보다 약 2.5배 — Extended Thinking 비용이 추가됐기 때문. 품질·정확도 trade-off로 합리적 수준 판단.
