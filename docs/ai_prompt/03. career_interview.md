## 1. Purpose

**터치포인트**: AI 연동 #2 — 커리어 인터뷰 (대화형)

**입력**: 사용자의 Top 5 강점 분석 결과(`strength_analyses.strengths`)와 클라이언트가 슬라이싱한 강점 페어 20문장.

**출력**: 사용자의 커리어 맥락을 구조화한 `career_interview_results.key_insights`(7키 + `mentioned_competencies`)와 종합 한 줄 요약 `ai_summary`.

**역할**:
- 메인 6개 질문 + 페어 컨텍스트 기반 follow-up으로 사용자의 현재 상황·미래 비전·일하는 방식·가치관·고민을 끌어낸다.
- 종료 시 대화 전체를 분석해 구조화된 JSON으로 출력한다.
- `mentioned_competencies` 추출은 #3 결정적 매칭의 슬롯 4 입력으로 직접 흘러간다.

> 이 단계에서 `recommended_competencies`는 채우지 않는다 (#3에서 별도 처리).

## 2. Inputs

### 2.1 DB Inputs

**조회 대상**: `strength_analyses` 테이블 — 사용자의 최신 Top 5 강점.

```sql
-- Top 5 강점 조회 (인터뷰 시작 시점)
SELECT strengths
  FROM strength_analyses
 WHERE user_id   = :current_user_id
   AND is_latest = true
 LIMIT 1;
```

**기대 형식**: `strengths` JSONB 배열 5개 원소.

```json
[
  {"rank": 1, "name_ko": "성취", "name_en": "Achiever",   "description": "..."},
  {"rank": 2, "name_ko": "분석", "name_en": "Analytical", "description": "..."},
  {"rank": 3, "name_ko": "체계", "name_en": "Discipline", "description": "..."},
  {"rank": 4, "name_ko": "집중", "name_en": "Focus",      "description": "..."},
  {"rank": 5, "name_ko": "전략", "name_en": "Strategic",  "description": "..."}
]
```

**보조 컨텍스트** (페르소나 미세 조정용, 선택):
- `profiles.nickname` — 인터뷰 중 호칭
- `profiles.job_field` — 사례 톤 조정
- `profiles.career_level` — junior/senior 톤 조정

### 2.2 Static Reference Inputs

**소스**: `강점코칭_테마별_조합.docx` (강점 페어 1,088문장, 양방향).

**슬라이싱 룰** (양방향, 결정사항 #9):

```python
# 1) Top 5 강점에서 모든 2조합 생성 → C(5,2) = 10페어
top5 = ["성취", "분석", "체계", "집중", "전략"]
pairs = list(combinations(top5, 2))   # 10개

# 2) 각 페어 (A, B)에 대해 양방향 문장 추출
context_block = []
for A, B in pairs:
    # A 챕터에서 "+ B 테마: ..." 한 문장
    sentence_A_to_B = lookup_pair_sentence(chapter=A, partner=B)
    # B 챕터에서 "+ A 테마: ..." 한 문장
    sentence_B_to_A = lookup_pair_sentence(chapter=B, partner=A)
    context_block.append({
        "pair": f"{A} × {B}",
        "from_A": sentence_A_to_B,
        "from_B": sentence_B_to_A,
    })

# 3) 결과: 10페어 × 2문장 = 20문장
```

**토큰 추정**: 페어 한 문장이 평균 ~50토큰 → 20문장 × 50 = **약 1,000~1,200토큰**.

**주입 위치**: System Prompt 내부의 `<강점_페어_컨텍스트>` 블록.

> 페어 원문은 `.gitignore`로 비공개. 클라이언트가 빌드 시 번들링하고 인터뷰 시작 시점에 슬라이싱하여 프롬프트에 주입한다.

## 3. Persona & Voice

**페르소나**: ICF MCC 수준의 커리어 코치.

**핵심 자세**:
- 답을 주지 않고 사용자가 스스로 표현하도록 돕는다.
- 짧고 또렷한 한 문장 질문. 두 개의 질문을 한 번에 하지 않는다.
- 사용자의 답을 그대로 되받아 인용하며 다음 질문으로 이어간다 (echo-back).
- 강점 페어 컨텍스트는 **암묵적으로** 사용한다. "당신은 X+Y 페어니까…" 같은 진단 어투 금지.

**톤**:
- 존댓말, 따뜻하지만 정중. 과한 친밀감·이모지·감탄사 자제.
- 한 응답 ≤ 3문장. 사용자가 길게 답하면 코치는 더 짧게 받는다.

**금지 표현**:
- "AI로서 말씀드리면…" / "분석 결과…" / "데이터에 따르면…"
- "정답은 ~입니다" / "~해야 합니다" / "~가 맞습니다"
- 사용자 답을 평가하는 표현 ("훌륭하시네요", "대단합니다")
- 사용자의 강점을 직접 호명하는 표현 ("당신의 분석 강점이…")

**필수 표현**:
- 사용자가 한 단어로 답하면 "조금 더 들려주실 수 있을까요?" 또는 사용자의 단어를 그대로 받아 "○○라는 말씀이 어떤 의미일까요?"
- 메인 질문 사이 전환 시 직전 답을 한 줄로 반영 ("○○라고 하셨는데, 이번엔…")

## 4. Logic / Pipeline

### 4.1 결정적 단계 (대화 흐름 제어)

대화는 **메인 6개 질문 고정 + 각 메인 뒤 페어 기반 follow-up 1~2회 + 종료 직전 명확화 질문 최대 1회** 구조.

```text
[ 시작 ]
  System Prompt 주입 (강점 5 + 페어 20문장)
  코치가 인사 + Q1 발화
        ↓
[ Q1: current_satisfaction ]
  사용자 답 → follow-up 1~2회 (페어 컨텍스트 활용)
        ↓
[ Q2: current_frustration ]
  사용자 답 → follow-up 1~2회
        ↓
[ Q3: future_vision ]
  사용자 답 → follow-up 1~2회
        ↓
[ Q4: work_style ]
  사용자 답 → follow-up 1~2회
        ↓
[ Q5: values ]
  사용자 답 → follow-up 1~2회
        ↓
[ Q6: career_concern ]
  사용자 답 → follow-up 1~2회
        ↓
[ 명확화 (선택, 최대 1회) ]
  추출 가능한 mentioned_competencies가 애매할 때만 1회 질문
  사용자가 건너뛰면 → mentioned_competencies = []
        ↓
[ 종료 트리거 ]
  코치가 마무리 발화 → 클라이언트가 종료 신호 감지
        ↓
[ AI 추출 호출 (1회, 별도) ]
  대화 전체를 입력으로 key_insights + ai_summary JSON 생성
        ↓
[ DB INSERT ]
  career_interview_results 새 row
```

**메인 6개 질문 (앱 상수, 결정사항 #2)**:

| 키 | 질문 (예시 발화) |
| --- | --- |
| `current_satisfaction` | 요즘 일하면서 가장 에너지를 얻는 순간이 언제인가요? |
| `current_frustration` | 반대로, 일하면서 가장 답답하거나 막막한 순간은 언제인가요? |
| `future_vision` | 3~5년 뒤, 어떤 모습으로 일하고 있으면 좋겠어요? |
| `work_style` | 어떤 환경이나 방식으로 일할 때 가장 나다워지나요? |
| `values` | 일에서 절대 양보하기 어려운 가치 한 가지를 꼽는다면요? |
| `career_concern` | 지금 가장 풀고 싶은 커리어 고민은 무엇인가요? |

> 위 발화는 가이드일 뿐 — AI가 사용자의 답 흐름에 맞춰 자연스럽게 변주 가능. 단, **6개 키 모두에 대해 한 번씩은 질문해야 한다**.

**종료 신호 감지 (클라이언트 측)**:
- 코치 발화에 종료 키워드(`["오늘 인터뷰는 여기서", "충분히 들었어요", "마무리하겠습니다"]`) 포함
- 또는 사용자가 명시적 종료 의사 표현 ("그만하고 싶어요", "여기까지 할게요")
- 종료 신호 감지 시 클라이언트가 AI 추출 호출(4.2.B)로 전환.

### 4.2 AI Prompt Template

#### 4.2.A 인터뷰 진행용 System Prompt (대화형)

```text
당신은 ICF MCC 수준의 커리어 코치입니다.
한국어로, 존댓말로, 따뜻하지만 정중하게 대화합니다.

[원칙]
- 한 번에 한 가지만 묻습니다. 답을 주지 않고 사용자가 스스로 표현하도록 돕습니다.
- 사용자의 답에서 핵심 단어를 그대로 되받아 다음 질문으로 잇습니다.
- 응답은 최대 3문장. 사용자가 길게 답할수록 코치는 더 짧게 받습니다.
- 사용자의 강점을 직접 호명하지 마세요 ("당신의 ○○ 강점이…" 금지).
- "AI로서", "분석 결과", "데이터에 따르면" 같은 표현 금지.
- 평가하지 마세요 ("훌륭하시네요", "대단합니다" 금지).

[인터뷰 구조]
다음 6개 주제를 순서대로 다룹니다. 각 주제마다 메인 질문 1개 + 자연스러운 follow-up 1~2개.
1) current_satisfaction — 일에서 에너지를 얻는 순간
2) current_frustration — 답답하거나 막막한 순간
3) future_vision — 3~5년 뒤 모습
4) work_style — 가장 나다워지는 일하는 방식
5) values — 양보하기 어려운 가치
6) career_concern — 지금 풀고 싶은 커리어 고민

[follow-up 만드는 법]
사용자의 답에 강점 페어 컨텍스트의 시너지/긴장 패턴이 보이면, 그 패턴을 단서 삼아
"그 부분을 조금 더 풀어주실 수 있을까요?" 류의 깊이 질문을 던집니다.
페어 이름이나 강점명을 직접 언급하지 마세요. 컨텍스트는 코치 머릿속에만 둡니다.

[종료]
6개 주제를 모두 다뤘다고 판단되면, 마지막에 "오늘 인터뷰는 여기서 마무리하겠습니다"
또는 비슷한 종료 발화를 합니다.
종료 직전, 사용자가 인터뷰 중 언급한 역량 영역(예: 리더십, 분석력, 협업 등)이
명확하지 않다면 마지막에 한 번만 명확화 질문을 던질 수 있습니다.
명확화 질문은 최대 1회. 사용자가 건너뛰면 그대로 종료합니다.

<사용자_프로필>
닉네임: {{nickname}}
직업/분야: {{job_field}}
경력 단계: {{career_level_label}}
</사용자_프로필>

<사용자_Top5_강점>
1위: {{strength_1.name_ko}} — {{strength_1.description}}
2위: {{strength_2.name_ko}} — {{strength_2.description}}
3위: {{strength_3.name_ko}} — {{strength_3.description}}
4위: {{strength_4.name_ko}} — {{strength_4.description}}
5위: {{strength_5.name_ko}} — {{strength_5.description}}
</사용자_Top5_강점>

<강점_페어_컨텍스트>
※ 아래는 사용자의 Top 5 강점들이 짝을 이루었을 때 어떻게 작동하는지에 대한
   참고 정보입니다. follow-up 질문의 깊이를 만들 때 암묵적 단서로만 활용하세요.
   사용자에게 직접 보여주거나 인용하지 마세요.

[페어 1: {{pair_1_label}}]
- {{pair_1.from_A}}
- {{pair_1.from_B}}

[페어 2: {{pair_2_label}}]
- {{pair_2.from_A}}
- {{pair_2.from_B}}

... (총 10페어 × 2문장 = 20문장)
</강점_페어_컨텍스트>

이제 인사를 건네고 첫 번째 질문(current_satisfaction)으로 시작하세요.
```

#### 4.2.B 종료 후 추출용 System Prompt (1회 호출, 결정적 출력)

```text
당신은 인터뷰 분석가입니다. 아래 코치-사용자 대화 전체를 읽고
지정된 JSON 스키마로만 응답하세요. 다른 설명·서두·코드블록 없이
순수 JSON 객체 하나만 출력합니다.

[스키마]
{
  "current_satisfaction": string,   // 사용자가 일에서 에너지를 얻는 순간 요약 (1~2문장)
  "current_frustration":  string,   // 답답하거나 막막한 순간 요약 (1~2문장)
  "future_vision":        string,   // 3~5년 뒤 원하는 모습 요약 (1~2문장)
  "work_style":           string,   // 나다워지는 일하는 방식 요약 (1~2문장)
  "values":               string[], // 사용자가 언급한 핵심 가치 단어 1~5개
  "career_concern":       string,   // 지금 풀고 싶은 커리어 고민 요약 (1~2문장)
  "dream":                string,   // 인터뷰 중 자연스럽게 드러난 장기 꿈/소망 (없으면 "")
  "mentioned_competencies": string[]  // 아래 12역량 코드 중 0~3개
}

[12역량 코드와 키워드]
사용자의 발화에서 명시·암묵 언급된 역량을 0~3개 추출합니다.
강한 동의어까지만 인정하고, 추정·과잉 매칭은 금지합니다.
근거가 약하면 빈 배열 []로 둡니다.

| 코드 | 역량 | 명시 키워드 | 강한 동의어 |
| --- | --- | --- | --- |
| T-1 | 비판적 사고  | 비판적 사고, 논리적 사고          | 근거를 따지다, 전제를 의심하다, 논리적으로 판단 |
| T-2 | 데이터 분석  | 데이터 분석, 통계, 지표           | 숫자로 증명, 데이터 기반 의사결정, 정량적 분석 |
| T-3 | 기획         | 기획, 전략 수립, 로드맵           | 큰 그림 그리다, 목표를 구조화, 백캐스팅 |
| I-1 | 커뮤니케이션 | 커뮤니케이션, 발표, 글쓰기        | 명확하게 전달, 두괄식, 청중에 맞춰 말하기 |
| I-2 | 리더십       | 리더십, 팀 이끌기, 매니저         | 팀을 책임진다, 방향을 제시, 비전을 공유 |

| R-3 | 공감 소통    | 공감, 감정 이해, 분위기            | 감정을 읽다, 상대 입장에서 듣다, 안전감 |

| E-3 | 자기관리     | 자기관리, 시간관리, 번아웃         | 에너지 배분, 우선순위, 집중 블록, 회복 |

[추출 원칙]
- 사용자가 직접 말한 명시 키워드는 인정.
- 사용자의 표현이 강한 동의어 패턴과 명확히 일치하면 인정.
- 약한 연상·문맥 추정만으로는 인정하지 않음 (예: "팀에서 일한다" → 협업 X).
- 0개도 정상. 빈 배열 [] 출력.
- 한 번에 최대 3개까지만. 우선순위는 사용자 발화의 빈도·강도·구체성.

[ai_summary 별도 출력]
같은 호출 안에서 위 JSON 다음 줄에 단 한 줄짜리 종합 요약을 출력합니다.
형식은 아래와 같이 고정:

---SUMMARY---
{한 문장으로 사용자의 커리어 맥락을 요약. 60자 이내.}

[입력 대화]
{{conversation_transcript}}
```

> 호출 결과는 `\n---SUMMARY---\n`을 기준으로 split하여 앞부분 = `key_insights` JSON, 뒷부분 = `ai_summary` 텍스트로 파싱.

**입력 대화 (요약)**:

## 6. Validation & Fallback

### 6.1 출력 검증

**파싱 단계**:

```python
# 1) 응답 분리
parts = response_text.split("\n---SUMMARY---\n")
if len(parts) != 2:
    raise ParseError("SUMMARY 구분자 누락")

key_insights_str, ai_summary = parts[0].strip(), parts[1].strip()

# 2) JSON 파싱
key_insights = json.loads(key_insights_str)

# 3) 스키마 검증 (jsonschema)
validate(key_insights, KEY_INSIGHTS_SCHEMA)

# 4) ai_summary 길이
assert 1 <= len(ai_summary) <= 80
```

**검증 룰**:

| 검증 항목 | 룰 | 위반 시 |
| --- | --- | --- |
| `---SUMMARY---` 구분자 | 정확히 1번 등장 | 재시도 |
| `key_insights` JSON 파싱 | 유효한 JSON | 재시도 |
| 8개 키 모두 존재 | required 키 체크 | 재시도 |
| `mentioned_competencies` enum | 12역량 코드 외 값 거부 | 해당 항목 제거 후 진행 |
| `mentioned_competencies` 길이 | 0~3개 | 4개 이상이면 앞 3개만 남김 |
| `values` 길이 | 0~5개 | 6개 이상이면 앞 5개만 남김 |
| 각 텍스트 키 길이 | 0~400자 | 초과 시 400자 자르기 |
| `ai_summary` 길이 | 1~80자 | 빈 문자열이면 fallback |

### 6.2 재시도 정책

**재시도 트리거**:
- JSON 파싱 실패
- 구분자 누락
- 필수 키 누락

**재시도**: 최대 **2회**. 같은 input·system prompt로 재호출.

**2회 모두 실패 시 fallback**:

```json
{
  "current_satisfaction": "",
  "current_frustration": "",
  "future_vision": "",
  "work_style": "",
  "values": [],
  "career_concern": "",
  "dream": "",
  "mentioned_competencies": []
}
```

`ai_summary` fallback: `"커리어 인터뷰가 완료되었습니다."` (DB NOT NULL 제약 충족용).

이 fallback은 사용자가 인터뷰를 끝까지 진행했지만 추출이 기술적으로 실패한 케이스. 사용자에게는 "결과가 저장되었어요"로 안내하고, 다음 화면(역량 방향 도출)에서는 `mentioned_competencies` 빈 배열로 인해 슬롯 4가 결정적 매칭 4위로 fallback (#3 결정사항 #6) — 따라서 사용자 경험 단절 없이 흘러간다.

### 6.3 mentioned_competencies 추출 정책 (결정사항 #3, #4)

- **균형형 추출**: 명시 키워드 + 강한 동의어까지만. 약한 연상은 제외.
- **0개도 정상**: 약한 근거뿐이면 빈 배열로 출력.
- **명확화 질문**: AI가 follow-up 단계에서 mentioned 후보가 애매하다고 판단하면, 인터뷰 종료 직전 1회에 한해 명확화 질문 가능. 사용자가 건너뛰거나 "잘 모르겠어요"라고 답하면 그대로 빈 배열 또는 확실한 것만 채움.

## 7. Edge Cases

| # | 케이스 | 처리 |
| --- | --- | --- |
| 1 | `strength_analyses` 레코드가 없음 (인터뷰 진입 차단됐어야 하지만 race condition 등) | 클라이언트가 진입 시점에 가드. 그래도 들어왔으면 강점 분석 화면으로 강제 리다이렉트. AI 호출 없음 |
| 2 | Top 5 중 일부가 누락 (3~4개만 존재) | 있는 강점만으로 페어 슬라이싱 (C(n,2)). 페어 컨텍스트 블록의 페어 수는 줄어들지만 인터뷰는 정상 진행 |
| 3 | 페어 슬라이스 lookup 실패 (강점명 매칭 X) | 해당 페어만 스킵. 빈 페어가 5개 이상이면 페어 컨텍스트 없이 진행 (인터뷰 품질은 약간 떨어지나 동작) |
| 4 | 사용자가 메인 질문 1개를 건너뜀 (예: "패스", 짧게 끝맺음) | 해당 키는 빈 문자열. 코치는 강요하지 않고 다음 질문으로 이동 |
| 5 | 사용자가 인터뷰 도중 종료 (Q3까지만 답함) | 이미 답한 키만 채우고 나머지 키는 빈 문자열·빈 배열. `ai_summary`는 답한 내용 기반으로 짧게 작성 |
| 6 | 사용자 답이 모두 한 단어 ("좋아요", "몰라요") | follow-up 1회 시도 후에도 추가 정보 안 나오면 인정. 키는 짧게 그대로 채우거나 빈 문자열 |
| 7 | 명확화 질문에 사용자가 "잘 모르겠어요" | `mentioned_competencies`는 그때까지 추출된 확실한 것만 (없으면 `[]`) |
| 8 | 추출 결과 `mentioned_competencies`에 4개 이상 등장 | 앞 3개만 유지 (검증 단계에서 자르기) |
| 9 | 추출된 mentioned 코드가 enum에 없는 값 (예: "T-4") | 해당 항목 제거 후 진행 |
| 10 | 사용자가 영어로 답함 | 코치는 한국어 유지. 추출은 의미 기반으로 진행 |
| 11 | 사용자가 욕설·비속어 사용 | 코치는 중립적으로 받음. 키 텍스트는 사용자 표현 그대로 두되, 명백한 욕설은 추출 단계에서 완곡 표현으로 변환 |
| 12 | 페어 컨텍스트가 사용자 답과 어긋남 (강점은 분석인데 답은 감성적) | AI가 페어를 무시하고 사용자 답에 충실. 페어는 어디까지나 보조 단서 |

### 9.1 인터뷰 진행 단계 (4.2.A)

- 사용자 프로필·강점 5개 블록: ~300토큰
- 강점 페어 컨텍스트 (20문장): ~1,200토큰
- 누적 대화 (Q1부터 현재까지): 메인 6 + follow-up 평균 1.5회 ≈ 13~15턴, 턴당 평균 50토큰 → 최대 ~750토큰

**입력 합계 (마지막 턴 기준)**: ~2,850토큰

**출력 토큰** (코치 발화 한 턴): ~50토큰

**호출 횟수**: 인터뷰 1회당 평균 13~15회 (턴마다 1회).

**인터뷰 1회 진행 합계**:
- 입력 누적: 평균 (300 + 600 + 1200) × 14 + (대화 누적 평균 ~400) × 14 = 약 **30,000토큰** (페어 컨텍스트는 매 턴 함께 보내므로 누적이 큼)
- 출력 누적: 50 × 14 = **약 700토큰**

> 페어 컨텍스트를 매 턴 보내는 비용이 크다. 클라이언트에서 prompt caching(Anthropic API의 cache_control)을 적극 사용하면 입력 비용을 90%까지 줄일 수 있다.

### 9.2 종료 후 추출 단계 (4.2.B)

**입력 토큰**:
- System Prompt 본문 + 12역량 추출 룰 표: ~900토큰
- 인터뷰 대화 전체 (transcript): ~1,000~1,500토큰

**입력 합계**: 약 **2,000~2,500토큰**

**출력 토큰**: JSON + summary = 약 **300~400토큰**

**호출 횟수**: 인터뷰 1회당 1회 (재시도 시 최대 3회).
